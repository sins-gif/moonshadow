## 摘要

分层记忆系统以「重要度定层级、时间定衰减」压缩上下文。召回阶段如何融合**相关性**与**时效性**，
决定系统在两类查询上的表现：历史性提问（「当初为什么这么定」）要求陈旧但相关的证据优先；
状态性提问（「现在是什么」）要求新鲜证据优先。常见做法是加性线性组合
（`q = w₁·rel + w₂·recency + w₃·imp`）[1]。

本文证明：**在该形式下，不存在能同时召回正例与排除负例的阈值**（定理 5）。
反例的两条候选都满足各自层级的卡龄窗口，且分属不同用例。缺陷是形式性的，无法通过调参消除。
据此采用**有界乘性修正**（定义 3）：

```
q = r · ( f + (1 − f) · δ )
```

其中 `r` 为相关性分（定义 1），`δ ∈ (0,1]` 为衰减因子（定义 2），`f` 为时间下限。
定理 3 给出两候选次序可被时效性反转的充要条件 `r_A/r_B < m_B/m_A`；推论 1 给出其上确界 `1/f`——
**时效性只能在相关性差距不超过 `1/f` 倍时改变次序**。

本版把参数**落地为定值**：`f = 0.5925`（开发集与留出集可行窗交集 `[0.5225, 0.6600]` 的中点附近，
偏离半步 `0.00125`；中点是**步长依赖**量，见 §6.3），`θ = θ′ = 0.3941`（取消 `T6/T7` 的独立更高门槛；`f` 一变 `θ` 必须重标定，见 §6.6）。
在 `f = 0.5925` 下，两个集合的成对一致率都是 `1.000`。

本版记录了**四处 v1.1 结论的失效**（§7.2），并追加了 3 条**边界用例**（§6.3）：加性方案在新用例集上也拿到 `1.000`，**一致率表不能区分加性与乘性**——区分它们只能靠阈值可分离性（定理 5）与合成网格实验（§6.7）。但边界用例**恢复了另一种区分力**：连续敏感度插值与 50/50 平均从 `1.000` 降到 `0.962`，且都只在同一张用例上失败（§6.1）。

**关键词**：记忆召回；时间衰减；分数融合；阈值可分离性；评测集冻结；负结果

## 1 引言

### 1.1 问题

长上下文系统需要在有限预算内从海量历史中挑出少量片段。分层记忆（T0–T9）用两条独立机制做初筛：
**重要度定层级**（层级决定召回策略与保留期限），**时间定衰减**（半衰期决定旧得多快）。
初筛之后，剩余候选需要一个标量分数来排序。该分数的构造方式直接决定两类查询能否同时被满足：

- **历史性提问**（`Q_hist`）：「当初为什么放弃自建存储？」——标准答案是陈旧但高度相关的记录；
- **状态性提问**（`Q_stat`）：「目前线上跑的是哪个版本？」——标准答案是最新的记录，
  即使其字面相似度更低。

二者的要求方向相反。若把时效性作为与相关性并列的加权项，则这两类查询对权重的需求互斥。

### 1.2 本文工作

1. **形式化一个加性方案的可分离性缺陷**（定理 5）：构造一对窗口合法的正负例，使负例分数高于正例，
   故任何阈值都无法分离（§4.3、附录 A.3）。
2. **给出有界乘性修正的可反转条件与上确界**（定理 3、推论 1、推论 2，附录 A.2）。
   该形式保证时效性**不能**反转差距超过 `1/f` 倍的相关性。
3. **把参数从「待标定」推到「定值」**：`f = 0.5925`、`θ = θ′ = 0.3941`（§6.3、§6.6）。
4. **把评测集变成契约**：切分由冻结清单定义，留出集改了字节即违规（§5.1）；
   用例的负例由生产门逐张验证（见 spec §5.6）。
5. **记录四处 v1.1 结论的失效及其原因**（§7.2），并给出一张「数值来源与复核等级」表（§5.4）。

### 1.3 结论摘要

在本版用例集（开发集 26 条 / 留出集 9 条）上，三个方案并列 `1.000`：加性、乘性、按意图硬切换。
**连续敏感度插值与 50/50 平均是 `0.962`**，两者都只在 `24-t7-borderline` 上失败——
这是本版「边界用例恢复区分力」的直接证据，且区分方向支持**固定下限**（§6.1）。
加性仍与乘性并列满分，因此**加性与乘性之间的选型不能靠一致率**，
采纳乘性的理由是并列时取**自由度更小**的形式，加上它在边界用例上更稳。

时间下限的采纳值是 `f = 0.5925`：开发集窗 `[0.5000, 0.6600]` 与留出集窗 `[0.5225, 0.9800]`
的交集为 `[0.5225, 0.6600]`，中点为 `0.59125`。**留出集这次真起了约束作用**——它定住了交集的下界，
并定住了 `θ′` 的上界（§6.4）。代价是它被消耗了一次。

## 2 相关工作

**分层记忆与上下文压缩** 以层级与保留期限管理长期状态的做法见于 MemGPT [2]，
其以分页方式在有限上下文窗口内调度历史。本报告关注层级既定之后**召回排序**的融合形式。

**加性融合** 生成式智能体 [1] 的检索分数为三项加权和：时效性（按小时指数衰减）、
重要性（模型打分）、相关性（嵌入余弦）。该形式与本报告证明不可分离的加性方案（定义 4）同构，
其实现按等权归一后求和。

**名次融合** 倒排名次融合（RRF）[3] 通过融合名次而非分数规避量纲不可比的问题，
在混合检索（稀疏 BM25 [4] + 稠密向量 [7]）中是标准做法。本报告中它是七种对照方案之一（§6.1），
在本用例集上为 `0.812`（开发集）/ `0.667`（留出集）。

**时间衰减模型** 遗忘曲线 [5] 与记忆强度的幂律衰减 [6] 说明「随时间衰减」存在多种函数形式。
本报告采用半衰期形式 `δ = 0.5^(Δ/h)` 而非时间常数形式 `exp(−Δ/τ)`；后者在 `Δ = h` 时给出
`0.368` 而非 `0.5`，即标注的「半衰期」实际只相当于标注值的 `0.693` 倍（见 spec §0.4(b)）。

**说明** 本报告未重新实现任何外部系统；上述文献用于界定问题与对照方案的位置。

## 4 方法

### 4.1 相关性主轴

相关性由三项构成，权重和为 `1`，故 `r` 落在 `[0.027, 1]`（定理 1）。
权重分配的依据是「对不对题」优先于「重不重要」，后者优先于「是否命中实体」；
该分配未经实验约束，见 §6.8 与 §7.3。

### 4.2 有界乘性修正

**定理 1（值域）** `σ ∈ [0,1]`、`r ∈ [0.027, 1]`、`m ∈ (f, 1]`（`h > 0`）、`q ∈ (0.027f, 1]`。

**定理 2（单调性）** `q` 对 `σ, i, μ` 严格递增；`h > 0` 且 `r > 0` 时对 `Δ` 严格递减；
`Δ > 0` 时对 `h` 严格递增。

定理 2 的形式化含义是：**时间只向下修正分数，且修正幅度有上界**。

**定理 3（可反转判定）** 设两条候选 A、B，`r_A, r_B > 0`，则

```
q_B > q_A   ⟺   r_A / r_B  <  m_B / m_A
```

**推论 1（反转上确界）** 若 `r_A / r_B ≥ 1/f`，则时效性无法反转次序；且 `sup (m_B/m_A) = 1/f`。
取 `f = 0.5925`：`1/f = 1.687764`（六位小数）。

**推论 2（不可达）** `1/f` 是上确界而非最大值：取等需 `Δ_A = ∞`。

**定理 4（T0 与下限无关）** `h = 0` 时定义 2 给出 `δ = 1`，定义 3 给出 `m = 1`，
故 `q = r`，与 `f`、`Δ` 无关。

证明见附录 A.2。定理 3 的直观含义：**时效性只能在相关性差距不超过 `1/f` 倍时改变候选次序**，
这一上界与具体卡龄无关。把 `f` 从 `0.62` 放宽到 `0.5925`，等价于把可反转区间从
`(1, 1.612903)` 扩大到 `(1, 1.687764)`——**这是本版唯一一处改变可反转上界的改动**。

### 4.3 加性形式不可分离

**定理 5** 对定义 4 的加性形式 `a`，存在正例 P 与负例 N 使 `a_N > a_P`；
因此不存在任何阈值 `θ` 能同时满足「召回 P」与「排除 N」。

*证明（反例，完整算式见附录 A.3）*：取
`N = (T3, i=2, Δ=10, s=0.15, μ=0)`（来自 `09-gate-noise-and-window` 的 `exclude`，
该文件自称 `reason=score`，即「只有 `θ` 能挡住它」），
`P = (T5, i=3, Δ=30, s=0.72, μ=0)`（来自 `17-explicit-recall-admits-t8`，在 `expect_order` 内），则

```
a_N = 0.530218678  >  0.503607729 = a_P       （差 0.026610949）
```

召回 P 要求 `θ < 0.503608`，排除 N 要求 `θ > 0.530219`，两式互斥。∎

**这个反例的三条性质都必须交代，否则证明无效：**

1. **两条都窗口合法**：`T3` 无卡龄窗口；`P` 的 `Δ = 30` 恰好落在 `T5` 的 `30` 天上界内
   （定义 6 是 `≤`，不是 `<`）。旧版见证取 `P = (T5, Δ=120)`，**超出窗口，证明无效**——
   该候选在真实流水线里会被窗口挡掉，它根本不是 `θ` 的证据。
2. **两条分属不同用例**（`N` 在开发集、`P` 在留出集）。`θ` 是**全局**阈值，
   跨用例的反例比同用例更强。
3. **两条都无实体命中**（`μ = 0`）。旧版文档把 `P` 的 `μ` 写作 `0.5`，与用例文件不符。

定理 5 说明：**加性形式的缺陷不是参数选择不当，而是形式本身不可分离**。
这是必须更换融合形式、而非调整权重的依据。

**一条必须同时说清的边界**：定理 5 是**构造性**结论（证据档：定理），它不依赖任何用例集。
因此即使加性方案在某一份用例集上恰好可分离（§6.6 显示它在**开发集**上可行），
定理 5 依然成立——它说的是「不存在对全部合法候选都有效的阈值」。

## 5 实验设置

### 5.1 用例集与冻结协议

每个用例包含一次查询、一批候选（层级、重要度、卡龄、相似度、实体命中）、
**人工标注的期望次序**，以及一批**负例断言**：

| 字段 | 含义 |
|---|---|
| `candidates` | 正例：必须过门、必须参与排序 |
| `expect_order` | 期望次序（正例的子序列） |
| `exclude` | 负例断言：每张都必须被门挡住，`reason ∈ {score, window, tier}` 说明是哪个规则 |
| `intent` / `needs_fresh` | 标签。开发集用 `intent`，留出集用 `needs_fresh` |
| `explicit_recall` | `T8/T9` 正例的前置声明 |

**切分是契约，不是目录现状。** 唯一真相源是 `eval/split-manifest.json`（种子 `20260601`，
留出比例 `0.3`）：开发集 `22` 条、留出集 `9` 条，每条留出用例带 `sha256`。
留出集改一个字节即违规；开发集允许增长，但清单里记录的开发用例不得消失。
强制手段是 `tools/run_split_integrity.py`（违规退出码 `1`）。

| 集合 | 条数 | 正例 | 负例 | 用途 | 标签 |
|---|---|---|---|---|---|
| 开发集 `eval/rank/` | 23 | 43 | 10 | 提出假设、扫描参数 | `intent` |
| 留出集 `eval/holdout/` | 9 | 19 | 1 | 检验假设（**冻结**） | `needs_fresh` |

开发集比清单多出的 `1` 条是**冻结后新增**的 `22-t9-noise-blocked-by-tier`，
用于覆盖 `T9` 的负例侧（`run_split_integrity.py` 会把它作为「新增开发用例」列出，
而不是判为违规）。

留出集用 `needs_fresh`（答案是否依赖最新状态）作为真值标签，而非 `intent`：
后者的边界不可判定——「张三的报价给到了吗」在「任务跟进」与「当前状态」之间没有客观归属，
而「是否依赖最新状态」有。

**为什么要冻结**：v1.1 的留出集在用例重写过程中被就地修改过（`H02`/`H03`/`H05`），
于是它不再是留出集，「留出集验证了某参数」这句话也无法追溯。冻结把这类修改从**静默**
变成**必须显式重新冻结并给出理由**（唯一合法途径是 `tools/resplit_cases.py --seed … --apply`）。

### 5.2 指标

1. **成对一致率**：期望次序的全部候选对中，产出次序与其一致的比例。
2. **`f` 落带率**：某策略选出的 `f` 落在该用例可行区间内的比例。该指标替代了
   「时效性二分类准确率」——后者对本任务缺乏因果性（§6.5）。
3. **阈值可分离性**：给定正负例分数集，是否存在阈值区间 `(max a_N, min a_P)`。
4. **可行性区间**：使全部用例正确排序的 `f` 的集合，以步长 `0.0025` 扫描得到
（`FLOOR_SWEEP_STEP = 0.0025`，`[0,1]` 上 `401` 个点；步长必须整除采纳值，否则扫描会漏掉采纳值）。
5. **约束产率**（v1.2 新增）：一批新增用例中，使**逐用例**可行区间宽度严格小于 `1.000`
   的用例占比。宽度为 `1.000` 意味着任何 `f` 都通过，即该用例对 `f` 不构成约束（§6.9）。

### 5.3 协议

全部方案调用同一份打分代码（`scoring.score_card` 的 `scheme` 参数），不使用平行实现。
`f` 由开发集扫描得到，随后在留出集上检验；两集合的可行区间分别计算并求交（§6.3）。
阈值由 `calibrate_thresholds` 分别在三组集合（开发集 / 留出集 / 合并）上标定（§6.6）。

**分数型负例的分布是标定能力的上界**：开发集有 `3` 条 `reason=score` 的负例参与 `θ` 标定、
`2` 条参与 `θ′`；**留出集一条都没有**（它唯一的负例是 `reason=tier`）。
所以「负例上界」完全由开发集给出，留出集只提供**正例下界**。这一点在 §6.4、§7.3 反复用到。

## 6 结果与分析

### 6.1 融合形式：边界用例恢复了区分力（区分方向支持固定下限）

在开发集 26 条上测七种方案（`tools/run_rank_eval.py`）：

| 方案 | 融合算术 | 上下文来源 | 开发集一致率 | 留出集一致率 | 开发集失败 |
|---|---|---|---|---|---|
| 加性（定义 4） | 加性 | 无 | **`1.000`** | **`1.000`** | 0/26 |
| **乘性修正（固定 `f = 0.5925`，采纳）** | 乘性 | 无 | **`1.000`** | **`1.000`** | 0/26 |
| 乘性 + 按意图硬切换 | 乘性 | oracle 意图 | `1.000` | `1.000` | 0/26 |
| 乘性 + 连续敏感度插值 | 乘性 | 措辞推断 | **`0.962`** | `1.000` | `24` |
| 两种分数 50/50 平均 | 分数平均 | 措辞推断 | **`0.962`** | `1.000` | `24` |
| 仅相关性 + 时间破同分 | 无 | — | `0.731` | `0.778` | `02`/`05`/`06`/`23`/`25`/`H02`/`H05` |
| RRF 名次融合 | RRF | 措辞推断 | `0.756` | `0.667` | `06`/`07`/`19`/`24`/`25`/`H02`/`H08` |

（留出集一列为直算值，见 §5.4：**未复核**。）

**本轮的实质变化：R1 边界用例把区分力还回来了。** 加入 `23`/`24`/`25` 之前，
五个方案并列 `1.000`，这张表对「时间话语权该由谁决定」没有任何区分力。
现在**连续敏感度插值与 50/50 平均降到 `0.962`，且都只在 `24-t7-borderline` 上失败**。

失败原因必须写准：`24` 的查询含「现在」，敏感性被**正确**识别为 `1.0`，
`floor_for_sensitivity` 据此把下限压到 `TIME_FLOOR_MIN = 0.35`，时间话语权变大，
于是「更新但相关性更低」的 `T7` 翻盘，与原则 (a) 相反。
**这不是漏判造成的**——连续插值正确地识别出「这条查询关心时效」，然后据此做出了错误的取舍。

**v1.1 的原结论是「加性形式的排序一致率反而更高（`0.970`），其缺陷只在阈值可分离性上暴露」。**
该结论**已失效**：加性在本用例集上也拿到 `1.000`，开发集与留出集都满分。
失效有两个可直接核对的原因：

1. **加性唯一的失败点被修掉了。** v1.1 §5.1.1 记录：加性在**第 03 号用例**失手——
   「一张完全相关但一年前的决策卡，会输给一张只是沾边的刚发生的新卡」。
   该用例的 `old-quote` 原为 `Δ = 120` 天，**超出 `T5` 的 30 天窗口**；
   场景重写后改为 `Δ = 28` 天（用例文件的 `note` 里记有 `**场景重写（P0）**`）。
   改到窗口内之后，这张卡不再受窗口压制，加性方案在该处的排序随之正确。
2. **切分重新随机化。** 该用例（`03-task-continuation`）在本版被分到**留出集**，
   而加性的另一处压力点（最弱正例 `17-explicit-recall-admits-t8` 的 `paraphrase`）同样在留出集。

**必须强调这不是「加性变好了」。** 定理 5 依然成立（§4.3）：它给出一对窗口合法的正负例，
说明**不存在**对全部合法候选都有效的阈值。一致率表看不出这件事——因为一致率只在
**每张用例内部的候选对**上统计，而定理 5 的反例是**跨用例**的。
这正是 v1.1 §7.3 第 3 条教训（「失败的性质比失败的次数更重要」）的第二次应验：
修好一张非法卡，同时**移除了某个方案的唯一反证**。

**采纳决定因此改由三条依据支撑**（前两条与一致率无关，第三条是新增的）：

- **并列时取自由度更小的形式**：固定下限的乘性修正不依赖意图识别组件，
  而 `T6/T7` 的额外选择性已由 `7` 天窗口表达（spec §0.4(c)）；
- **加性的形式缺陷有构造性证明与独立的合成网格证据**（§4.3、§6.7），
  乘性方案的上界在网格上违反 `0` 组；
- **在边界用例上更稳**：`1.000` vs 连续插值/50-50 的 `0.962`（上一轮没有这条证据）。

连续敏感度插值与按意图硬切换的实现**刻意保留**，只为让 §6.2 的消融可复现；它们不是推荐路径。

按查询意图拆分（开发集，`f = 0.5925`）：

| 查询意图 | 加性 | 乘性（采纳） | 仅相关性 | 硬切换 | 连续插值 | RRF | 50/50 |
|---|---|---|---|---|---|---|---|
| 历史决策 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 0.000 | 1.000 |
| 长期偏好 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 |
| 当前状态 | 1.000 | 1.000 | 0.000 | 1.000 | 1.000 | 0.667 | 1.000 |
| 任务跟进 | 1.000 | 1.000 | 0.889 | 1.000 | 1.000 | 0.870 | 1.000 |

v1.1 曾用这张表的「任务跟进」一行区分加性与乘性（`0.917` vs `1.000`）。该差异在本版消失
（两者都是 `1.000`），与上文是同一次失效。

### 6.2 消融一：上下文信号（按意图切换 `f` 与连续插值）

| 方案 | 融合算术 | 上下文来源 | 开发集 | 留出集 |
|---|---|---|---|---|
| 乘性（固定 `f`，采纳） | 乘性 | 无 | `1.000` | `1.000` |
| + 按意图硬切换 `f` | 乘性 | 措辞推断 | `1.000` | `1.000` |
| + 按意图硬切换 `f` | 乘性 | oracle 意图 | `1.000` | `1.000` |
| + 连续敏感度插值 | 乘性 | 措辞推断 | **`0.962`** | `1.000` |
| RRF 名次融合 | RRF | 措辞推断 | `0.756` | `0.667` |
| 两分数 50/50 平均 | 分数平均 | 措辞推断 | **`0.962`** | `1.000` |

**结论：上下文信号不带来任何增量，连续插值还是负增量。** 这是本报告最初主张
（v1.1 之前主张「上下文来源是唯一没被榨干的维度」）后被自身实验否定的方案，
本版再次否证——而且这次是**两个**方向上的否证：按意图硬切换与固定下限并列
（没有增量），按敏感度连续插值则低于固定下限（有负增量，失败于 `24`）。

机制值得写清楚：连续插值把「时间该有多大话语权」交给查询措辞推断的连续量，
**推断本身是对的**（`24` 的「现在」被识别为 `1.0`），错的是据此作出的取舍——
在一张「相关性差距更大的一方本应胜出」的用例上，它调高了时间话语权。
固定下限没有这个自由度，因此不会犯这类错。

v1.1 的同一张表里，`f = 0.62` 下 50/50 平均只有 `0.970`，并据此写了「把加性混入会一并混入其
结构性缺陷」。这句话在本版**仍无数据支撑**：加性与 50/50 平均在 `24` 上的差别不是加性缺陷造成的
（加性在 `24` 上是 `1.000`）。结构性缺陷仍然存在，但它现在只能由 §4.3 的定理与
§6.7 的网格实验展示，不能由一致率展示。

### 6.3 消融二：`f` 的扫描与 `0.5925` 的确立

以步长 `0.0025` 扫描 `f ∈ [0,1]`，算术固定为有界乘性修正：

| 集合 | 全通过窗口 | 宽度 | 中点 |
|---|---|---|---|
| 开发集（26 条） | `[0.5000, 0.6600]` | `0.1600` | `0.5800` |
| 留出集（9 条） | `[0.5225, 0.9800]` | `0.4575` | `0.7512` |
| **交集** | **`[0.5225, 0.6600]`** | **`0.1375`** | **`0.59125`** |

采纳值 `f = 0.5925` 落在采纳网格上（`0.5925 = 237 × 0.0025`），与交集中点 `0.59125` 相差
`0.00125`＝**半个步长**。在 `f = 0.5925` 下两集合成对一致率均为 `1.000`。

**窗口宽度的来源是极少数用例**：

| 端点 | 用例 | 集合 |
|---|---|---|
| 交集下界 `0.5225` | `01-historical-decision` | 留出集 |
| 交集上界 `0.6600` | `23-t6-tight-race` | 开发集 |
| 开发集下界 `0.5000` | `24-t7-borderline` | 开发集 |
| 留出集上界 `0.9800` | `08-status-weak-signal` | 留出集 |

**交集的两个端点各由一条用例决定**，且端点是扫描网格点（步长 `0.0025`，真实边界在 `±0.0025` 内）。
因此 `0.5925` 这个数的诚实表述是「**落在 `(0.5225, 0.6600)` 内，取其中点附近**」，不是「等于 `0.5925`」。

**v1.1 关于窗口宽度的结论已失效，且失效原因与 v1.1 的措辞相反。**

| | v1.1 记录 | v1.2 实测（本版） |
|---|---|---|
| 开发集窗口 | `[0.608, 0.634]`，宽 `0.026` | `[0.5000, 0.6600]`，宽 `0.1600` |
| 留出集窗口 | `[0.466, 0.664]`，宽 `0.198` | `[0.5225, 0.9800]`，宽 `0.4575` |

那个窄窗是**用例缺陷造出来的**：9 张超出层级窗口的候选卡（跨开发集与留出集）
在乘性打分下时间修正几乎归零，于是把可行窗的一侧压到 `0.608–0.634`。
按窗口合法**重写场景**（不是截卡龄：用例条数不变）后，开发集窗口宽为 `0.1600`，是原来的 **`6.15` 倍**。
**「`f` 不可辨识」这一条在新用例集上不成立**；剩下的真问题是窗口端点由个别用例决定。

会把「无区分力」读成「有优劣」。此外本版采纳值是 `0.5925`，与该行的两个候选都不同。
#### 6.3.1 中点因数据而移动：一次数据驱动决策的四步因果链

`f` 的采纳值在本版经历了三次移动，每一次都能指到具体的数据变化。记在这里，
是为了让「参数是数据定的」这句话有据可查，而不是一句姿态。

1. **旧参数由超窗用例决定。** v1.1 的窗口 `[0.608, 0.634]` 与采纳值 `0.62` 是被
   **9 张超窗候选卡**压出来的（跨开发集与留出集；**是卡不是用例**——用例条数没变，
   修法是**重写场景**把卡龄改回窗口内）。修正后窗口放宽，中点移到 `0.605`。
2. **重划并冻结切分后，中点仍是 `0.605`。** 这一步只换了用例的归属，没有改变窗口。
3. **加入 3 条严格边界用例后，窗口收窄为 `[0.5225, 0.6600]`，中点移到 `0.5925`。**
   这 3 条是按 roadmap §7.1 的 R1 设计的（相邻候选分差 `≤ 0.05`），
   它们把开发集窗的两端各往里推了一段：上界由 `0.6850` 收到 `0.6600`，下界由 `0.4675` 抬到 `0.5000`。
4. **这 3 条立刻成为钉住窗口的用例，并恢复了方案区分力。** `23` 定上界、`24` 定下界（原钉住者 `H02`/`H04` 不再是约束）；
   同时 §6.1 里连续插值与 50/50 平均从 `1.000` 掉到 `0.962`，且同在 `24` 上失败。

**两条必须同时写明的限制：**

1. **中点是步长依赖的量，不是精确值。** 同一份用例集、同一套算术，不同分辨率的读数不同：

   | 扫描步长 | 交集中点 |
   |---|---|
   | `0.005` | `0.5925` |
   | `0.0025`（采纳网格） | `0.5913` |
   | `0.00125` | `0.5919` |
   | `0.0005` | `0.5922` |

   真值约 `0.592 ± 0.001`。取 `0.5925` 的理由是它落在采纳网格上、且与各分辨率的中点
   相差不超过半步——**不是**「它是精确中点」。另外注意 `run_rank_eval.py` 打印的
   「窗口中点 `0.5800`」是**开发集窗自身**的中点，与交集中点不是同一个量，引用时不能混用。

### 6.4 留出检验：这次留出集真的起了约束作用（并被消耗一次）

v1.1 的核心方法学教训是「留出集比开发集宽时，它不构成独立约束」。本版的结论**相反**：

| 留出集起的作用 | 证据 |
|---|---|
| 定住 `f` 交集的下界 | 交集下界 `0.5225` 来自留出集 `01-historical-decision`；若没有它，交集下界会是开发集的 `0.5000` |
| 定住 `θ′` 的上界 | 合并区间上界 `0.397591` 来自留出集 `03-task-continuation` 的 `T6` 正例 `unrelated-fresh`（§6.6） |
| 否证开发集单独给出的 `θ′` 取值 | 开发集单独给出的建议值 `0.412684` 会挡掉留出集 3 张真实 `T6` 正例（`0.397591`/`0.409062`/`0.410692`） |

因此本版**首次**出现「留出集改变了取值」的情形。这与 v1.1 的情形完全不同，必须分开记：
v1.1 的留出集只否掉极端值；本版的留出集**直接决定了两个参数的边界**。

**代价是它被消耗了一次。** 采纳 `θ′ = θ = 0.3941` 时用到了留出集的正例下界，
所以留出集对 `θ` 族参数**不再是干净的检验集**。任何后续改动 `θ`/`θ′` 的工作都必须先按
spec §5.5 重新冻结（`resplit_cases.py --seed <新种子> --apply`），否则「留出验证」四个字没有内容。

同时必须记录：留出集窗口仍然更宽（`0.4575` vs 开发集 `0.1600`），且**它不包含**开发集窗口。
它之所以能起作用，不是因为「窄」，而是因为**它的下界比开发集高**（`0.5225 > 0.5000`）。
「窄才有约束力」是错的表述；正确的表述是**边界的位置**决定谁有约束力。

### 6.7 稳健性：参数漂移下的反转区域

35 条用例只覆盖参数空间的一小块。
（`moonshadow.drift`，`tools/run_drift_check.py`）：正例取无卡龄窗口的 `T2/T3`，
卡龄 `5–800` 天、相似度 `0.70/0.85`；负例为低相似度、无实体命中、`0.1–15` 天、重要度 `1/2`。
共 `2304` 组配对。**本实验不读用例文件**（证据档：合成网格实验）。

| 方案 | 反转组数 | 占比 | 反转对里的最大 `r_P/r_N` | 落在乘性保证区内的反转 |
|---|---|---|---|---|
| 加性（定义 4） | `173` | `7.51%` | **`1.8844`** | **`117`** |
| 有界乘性（`f = 0.5925`） | `21` | `0.91%` | `1.6441` | 越界 `0` 组 |

**结构原因**：加性方案的分数含有一项 `0.25 δ`，它在相关性分 `r` 中没有对应项。
因此其反转条件里存在一个**与查询、与相关性都无关的年龄偏移**，年龄差可以独立推动反转。
乘性方案的反转条件（定理 3）是纯比值条件，且被 `1/f` 封顶（推论 1）：
`r_P/r_N ≥ 1/0.5925 = 1.687764` 时不得反转，实测越界 `0` 组，
反转对里的最大比值 `1.6441 < 1.687764`——**全部落在上界之内**。

**`f` 的改动在这张表上有一个必须交代的代价。** 加性方案的反转组数与 `f` 无关
（定义 4 不含 `f`），两次测量都是 `173`。但「落在乘性保证区内」的组数会随 `1/f` 变化：

| `f` | `1/f` | 乘性保证区 | 加性在保证区内的反转 | 乘性自身反转 |
|---|---|---|---|---|
| `0.62`（v1.1） | `1.612903` | `r_P/r_N ≥ 1.612903` | `142` | `4`（`0.17%`） |
| `0.5925`（本版） | `1.687764` | `r_P/r_N ≥ 1.687764` | `117` | `21`（`0.91%`） |

即：**放宽 `f` 让乘性方案允许的反转变多（`4 → 21`），同时让加性方案在保证区内的违反变少
（`142 → 117`）——因为保证区本身变小了。** 这是同一笔取舍的两面，
与 spec §5.7「参数之间不独立」一致。两组数字都不支持「放宽下限只有好处」。

**对漂移的回答**：若漂移主要改变**相似度量级**（例如更换嵌入模型），两方案同步受影响；
若漂移改变**卡龄分布**（真实语料必然如此），则只有加性方案的反转会增长，
且增长**不受任何相关性比值上界约束**——乘性方案那 `0.91%` 在任何卡龄分布下都不会越过 `1/f`。

须区分两件事：`f = 0.5925` 这个**取值**是在特定卡龄画像下调出的，漂移会使其不再最优；
而**上界 `1/f` 的存在性**与数据无关（推论 1 是定理），漂移不能使该保证失效。

### 6.8 相关性权重的敏感性：区域变大，当前值不再贴边（v1.1 结论失效）

`(w_σ, w_i, w_μ)` 的来源是**算术推导，而非判断**。v1.0 的加性权重为 `(0.45, 0.25, 0.20, 0.10)`；
把 `decay` 移入乘性修正后，其余三项按 `0.75` 重新归一化：

```
0.45 / 0.75 = 0.600（精确）     0.20 / 0.75 = 0.2667 → 0.27     0.10 / 0.75 = 0.1333 → 0.13
```

因此这三个数不携带任何独立依据。为判断其影响，在权重单纯形上扫描 `f = 0.5925` 下的成对一致率
（`sweep_weights`，步长 `0.01`，`5151` 个点）。**本节全部数字未复核**（可由 `sweep_weights` 直算，

| 可行区占比 | `38.9%` | `16.15%` |

**与 `f` 的对照**：`f = 0.5925` 位于自身可行区间的中点附近（偏离半步 `0.00125`），
而权重位于自身可行区域的内部但非中心点。两者都是「未被独立数据约束」的参数，
但前者的位置有明确的 minimax 依据，后者没有。

### 6.9 用例集的约束产率（新增指标）

35 条用例中，决定 `f` 可行窗的只有 `4` 条（§6.3），决定 `θ` 上界的只有 `1` 条（§6.6）。
为把这一现象量化，`tools/run_batch_audit.py` 对每批新增用例计算两个判定量：

- **边界用例**：期望次序中**相邻候选对**在当前采纳参数下的最小分差 `≤ 0.05`；
- **约束产率**：逐用例可行区间宽度 `< 1.000` 的用例占比（宽度 `1.000` 表示任何 `f` 都通过）。

**本轮新增的 `4` 条（`22`–`25`）**才是按 R1 设计的一批，工具判定 `exit 0`：

| 用例 | 相邻最小分差 | 可行区间 | 宽度 | 边界 | 约束 |
|---|---|---|---|---|---|

## 7 讨论

### 7.1 主要发现

1. **加性融合的缺陷是形式性的**（定理 5），且本版给出了**窗口合法、跨用例**的反例对。
   该缺陷在排序一致率上不可见——本版中加性与乘性并列满分。
2. **一个有界常数足以替代一层上下文机制**：上下文信号的三种变体均未超过固定 `f = 0.5925`（§6.2）。
3. **可反转上界是最准确的表述方式**：`f` 由 `0.62` 改为 `0.5925`，等价于把可反转区间
   从 `(1, 1.612903)` 扩大到 `(1, 1.687764)`（推论 1）。这一扩大有代价：乘性方案的
   网格反转组数由 `4` 升到 `21`（§6.7）。
4. **本次留出集真的起了约束作用**（定住 `f` 的下界与 `θ′` 的上界），代价是被消耗一次（§6.4）。
5. **一致率表不能区分加性与乘性，但能区分固定下限与上下文推断**：加性、乘性、按意图硬切换
   三者并列 `1.000`，而连续敏感度插值与 50/50 平均是 `0.962`（同在 `24` 上失败，§6.1）。
   因此「加性 vs 乘性」只能靠定理与合成网格实验（§3.4），而「固定下限 vs 上下文推断」可以直接靠一致率，
   且方向支持固定下限。
6. **R1 边界用例是提高约束力的有效手段**：按「相邻候选分差 `≤ 0.05`」设计的 3 条用例
   把 R1 从 `1/7` 拉到 `3/4`、R2 从 `0.000` 拉到 `0.750`（工具 `exit 0`），
   并顺带把开发集窗收窄、把区分力还回来（§6.3.1、§6.9）。
   凡是要区分融合形式的结论，只能靠定理与合成网格实验（§3.4）。

### 7.3 威胁有效性

**内部有效性。** 全部 35 条用例由人工编写，期望次序由人工标注。
留出集与开发集共享同一套数值设定（层级、卡龄、相似度量级），因此 §6.3–§6.4 检验的是
**同一设计假设下的参数泛化**，而非真实查询分布上的泛化。
`(w_σ, w_i, w_μ)` 的三项分配、十个半衰期、两个卡龄窗口在整个研究过程中固定，
**未受任何实验约束**——它们是占位值，全部结论在此占位值下测得。
§6.8 显示权重项落在可行区域内且距边界约 `11` 个网格步；十个半衰期与两个卡龄窗口
连这样一次扫描都还没做过。

**留出集已被消耗一次。** `θ′` 的上界由留出集的正例定出（§6.6 第 3 点）。因此对 `θ` 族参数而言，
本版之后不存在未被使用过的检验集。这是**有意的取舍**（否则要采信一个会挡掉 3 张真实正例的取值），
但它必须在每次引用「留出集验证」时一并声明。

**构造有效性。** 成对一致率对候选数敏感：候选少时单次错位影响更大。
参与标定的分数型负例只有 `3` 条（`θ`）与 `2` 条（`θ′`），且**全部来自开发集**——
留出集唯一的负例是 `reason=tier`，它不参与任何阈值标定。因此 `θ` 的**负例上界没有第二份数据**。

**外部有效性。** 用例数量（35 条）不足以支撑统计推断。
本报告已经两次见证用例集改变结论：v1.1 中从 6 条扩到 11 条推翻了一个结论；
本版中用例重写 + 重新切分推翻了四处，追加边界用例又移动了整族参数。真实查询分布数据是本结论外推的必要条件。

**冻结的效果与代价。** 冻结让「改留出集」必须走 `resplit_cases.py` 并给出理由，
代价是**发现缺陷时不能就地修**——v1.1 恰恰是就地修了（`H02`/`H03`/`H05`），
于是留出集失效而无人察觉。本版选择「改就要显式重冻结」，宁可多一步人工动作。

**独立于用例集的证据只有两类**：定理（§4.2、§4.3、附录 A.2–A.3）与合成网格实验（§6.7）。
本版把「是否更换融合形式」这个决定建立在这两类上，而不是建立在 §6.1 的一致性表上。

**方法论风险。** 部分方案（连续敏感度插值、RRF、50/50 平均）是在观察到前几组结果后加入的，
存在对当前用例集过拟合的风险。`f = 0.5925` 与 `θ = 0.3941` 都是在这些用例上扫出来/标定出来的
调参值，与人工判断值之间不构成公平比较；留出集限制了这种偏差，但已被消耗一次（如上）。

### 7.4 方法学教训

v1.1 的六条仍然成立，本版补三条：

1. **量纲不同源的信号不应放入同一加法式。** 强行定义「相关性—时效性」汇率，
   必然在某一类查询上失效（定理 5）。
2. **小样本上的「无差异」不等于「无差异」。** 6 条用例下三种融合算术完全一致，
   扩至 11 条后其中一种下降 `0.106`。应先扩样本再下结论。
3. **失败的性质比失败的次数更重要。** 结构性失败（补信息无法修复）与信息性失败（可修复）
   在聚合指标上可能相同，但决策方向相反。
4. **区分「机制不足」与「参数不当」。** 最昂贵的一次误判是把「默认下限偏高」误诊为
   「缺少上下文信息」，为此实现了一整层意图切换机制，而该机制经消融后被否定（§6.2）。
5. **中间指标须与目标存在因果关系。** 二分类准确率的错误可能全部无害（§6.5）。
6. **留出集比开发集宽时，它不构成独立约束**——但必须补上一句：
   **决定约束力的是边界的位置，不是宽窄。** 本版留出集仍更宽（`0.4575` vs `0.1600`），
   却因为下界更高而成为交集的实际约束（§6.4）。
7. **修用例会移除证据，必须记录移除了什么。** 把一张超窗卡改到窗口内，
   同时移除了加性方案唯一的失败点，使一致率表从「能区分」变成「不能区分」（§6.1）。
   改用例的提交说明里应写明「本次改动使哪条结论失去了证据」。
   **补用例则会造出证据**：按 R1 追加 3 条边界用例后，一致率表重新能区分
   固定下限与上下文推断（§6.3.1）。**用例的边界位置本身就是一种实验条件**，
   它和算术形式一样能决定结论，因此必须和参数一起记录。
8. **并列必须如实报并列。** 三个方案 `1.000` 时，任何「最高」的说法都是抽签结果。
   本版因此把 `run_rank_eval.py` 的结论行改为报告并列个数与名单；
   同理，`run_holdout.py` 那句「开发集最优是过拟合的直接证据」在两侧同为 `1.000` 时不成立（§6.3）。
9. **文档数值必须是断言，且断言两侧必须同源。** v1.1 把附录数值写成 `tests/` 断言，
   因此发现了 7 处第五、六位小数的错误——这条经验有效。本版又出现了它的反面一次：
   `tools/audit_appendix.py` 曾报 `6` 项不一致，原因正是**文档改了 `f` 而工具的期望值没改**。
   修法不是改数字，而是让工具**同时复核两列**（§A.6）——断言只有两侧同源时才有意义。
   同类守卫现已固化为 `tools/audit_docs.py`（赋值式与代码常量比对、链接、索引）。

## 8 结论

召回排序中，**相关性应当是主轴，时效性应当是门、有界修正与冲突裁决，而不是与相关性并列的权重**。
本文证明了加性形式在阈值可分离性上的形式性缺陷（定理 5，反例两条均窗口合法且跨用例），
给出有界乘性修正的可反转条件与上确界（定理 3、推论 1），
并把时间下限与硬门阈值落地为定值：`f = 0.5925`、`θ = θ′ = 0.3941`。

消融实验表明，按查询意图调节该下限**不带来增量**，按敏感度**连续插值则是负增量**
（`0.962` vs 固定下限 `1.000`，同在 `24-t7-borderline` 上失败，§6.1）。加性与乘性在本用例集上并列满分，
因此**一致率不能区分加法式与乘性式**——但它能区分「固定下限」与「把话语权交给上下文推断」，
且方向支持固定下限。最终建议因此是**降低一个常数，而非增加一层机制**，
并把这个决定建立在两类不依赖用例集的证据上：定理与合成网格实验。

适用范围受 §7.3 所列威胁限制：全部用例证据来自 35 条人工用例，
留出集已被 `θ′` 消耗一次，半衰期与卡龄窗口仍是未约束的占位值。
真实查询分布上的重估规则为：固定其余常量，扫描 `f`，记录全通过区间，
与重新冻结后的留出区间求交，并用 `run_gate_audit.py` 保证用例里的负例断言与生产门一致。

### A.2 定理 1–4 与推论 1–2 的证明

**定理 1（值域）**
(i) 由定义 `σ = (1+s)/2`：`s ≥ −1 ⇒ σ ≥ 0`；`s ≤ 1 ⇒ σ ≤ 1`。
(ii) 由 `i ∈ {1,…,10}` 得 `i/10 ∈ [0.1, 1]`，又 `μ ≥ 0`，故 `r ≥ w_i · 0.1 = 0.027`；
由 `w_σ + w_i + w_μ = 1` 且三项各自 `≤ 1`，得 `r ≤ 1`。
(iii) `h > 0` 时 `Δ/h ≥ 0`，故 `δ = 0.5^(Δ/h) ∈ (0, 1]`：`δ > 0` 给出 `m > f`；
`Δ = 0 ⇒ δ = 1 ⇒ m = 1`。`h = 0` 时 `m = f + (1−f) = 1`。
(iv) `q = r m`，由 (ii)(iii) 得 `0.027·(>f) < q ≤ 1`。∎

**定理 2（单调性）**
(a) `∂r/∂σ = w_σ > 0` 且 `m > 0`，故 `∂q/∂σ = w_σ m > 0`；
同理 `∂q/∂(i/10) = w_i m > 0`，`∂q/∂μ = w_μ m > 0`。
(b) `∂δ/∂Δ = 0.5^(Δ/h) ln(0.5) / h < 0`（`h > 0`），故 `∂m/∂Δ = (1−f) ∂δ/∂Δ < 0`（`f < 1`），
于是 `∂q/∂Δ = r (1−f) ∂δ/∂Δ < 0`（`r > 0`）。
(c) `∂δ/∂h = 0.5^(Δ/h) ln(0.5) (−Δ/h²) > 0`（`Δ > 0`，`ln 0.5 < 0`）。∎

**定理 3（可反转判定）**
`q_B > q_A ⟺ r_B m_B > r_A m_A`。两边同除正数 `r_B m_A`，得 `⟺ r_A/r_B < m_B/m_A`。∎

**推论 1（反转上确界）**
由定理 1(iii)，`m_B ≤ 1` 且 `m_A > f`，故 `m_B/m_A < 1/f`。
于是 `r_A/r_B ≥ 1/f` 时定理 3 右端不成立。
上确界在 `m_B = 1`（`Δ_B = 0`）与 `m_A → f⁺`（`Δ_A → ∞`）时逼近。
`f = 0.5925` 时 `1/f = 1.687764`。∎

**推论 2（不可达）**
取 `m_A = f` 需 `δ(Δ_A) = 0`，即 `Δ_A = ∞`，有限卡龄取不到。
（浮点实现下 `Δ ≈ 10⁹` 天时下溢，`m` 取等于 `f`；实数域上严格大于。）∎

**定理 4（T0 与下限无关）**
`h = 0` 时定义 2 给出 `δ = 1`，定义 3 给出 `m = f + (1−f) = 1`，故 `q = r`，与 `f`、`Δ` 无关。∎

### A.3 定理 5 的反例算式

| | 层级 | `i` | `Δ` | `s` | `μ` | 出处 |
|---|---|---|---|---|---|---|
| N（负例，应排除） | T3 | 2 | 10 | 0.15 | 0 | `09-gate-noise-and-window`（开发集）的 `exclude`，文件自称 `reason=score` |
| P（正例，应召回） | T5 | 3 | 30 | 0.72 | 0 | `17-explicit-recall-admits-t8`（留出集），在 `expect_order` 内 |

**两条都满足自身层级的卡龄窗口（定义 6）**：`T3` 无窗口；`T5` 的 `Δ = 30` 恰在 `30` 天上界内
（定义 6 用 `≤`）。**两条分属不同用例**：`θ` 是全局阈值，跨用例的反例比同用例更强。

```
σ_N = (1 + 0.15)/2 = 0.575        δ_N = 0.5^(10/90)  = 0.925874712
a_N = 0.45(0.575) + 0.25(0.925874712) + 0.20(0.2) + 0.10(0)
    = 0.258750    + 0.231468678       + 0.040000   + 0        = 0.530218678

σ_P = (1 + 0.72)/2 = 0.860        δ_P = 0.5^(30/14)  = 0.226430916
a_P = 0.45(0.860) + 0.25(0.226430916) + 0.20(0.3) + 0.10(0)
    = 0.387000    + 0.056607729       + 0.060000   + 0        = 0.503607729
```

`a_N > a_P`（差 `0.026610949`）。设 `θ` 为任一阈值：召回 P 要求 `θ < 0.503608`，
排除 N 要求 `θ > 0.530219`，互斥。∎

**本节三处勘误（v1.1 → v1.2）：**

| # | v1.1 的写法 | 事实 | 性质 |
|---|---|---|---|
| 1 | `P = (T5, i=3, Δ=120, s=0.70, μ=0.5)` | `Δ = 120` **超出 `T5` 的 30 天窗口**，该候选会被窗口挡掉，不是 `θ` 的证据；现行见证改为 `Δ = 30`、`s = 0.72`、`μ = 0` | **证明无效**（不是笔误） |
| 2 | `δ_N = 0.925874` | `δ_N = 0.925874712`，六位小数应为 **`0.925875`** | 舍入错误 |
| 3 | `μ_P = 0.5` | 该卡 `entities` 为空、`task_hit` 为假，`μ = 0` | 取值错误 |

「一张会被窗口挡掉的卡与另一张卡的分数关系」，与硬门行为无关。
这类错误只有把「用例文件里的字段」与「算式里的输入」逐格对齐才能发现（`tests/test_appendix_examples.py`
现在会断言两条见证卡确实存在于用例集、窗口合法、且 `reason`/`expect_order` 与角色一致）。

### A.4 数值实例

查询「缓存层换用什么方案了？」，两个候选均命中查询实体，故 `μ = 0.5`。
例题设计上让**新决定的重要度高于旧文档**（`i` 为 `4` 与 `5`）。

**本表保留两列**：`f = 0.5925` 是现行采纳值；`f = 0.62` 是历史值，
由用户自算脚本 `experiments/user_a4_candidate_a.py` 与 `_b.py` 逐格验算（两文件硬编码 `f = 0.62`，
不得修改）。**换 `f` 只改变 `m` 与 `q`；`r`、`δ`、`f*` 与 `f` 无关。**

| 量 | 候选 A（旧方案文档，T4） | 候选 B（新方案决定，T5） |
|---|---|---|
| `s` | `0.95` | `0.60` |
| `i` | `4` | `5` |
| `μ` | `0.5` | `0.5` |
| `Δ`（天） | `55` | `1.5` |
| `h`（天） | `30` | `14` |
| `σ = (1 + s)/2` | `0.975000` | `0.800000` |
| `w_σ σ` | `0.585000` | `0.480000` |
| `w_i (i/10)` | `0.108000` | `0.135000` |
| `w_μ μ` | `0.065000` | `0.065000` |
| **`r`** | **`0.758000`** | **`0.680000`** |
| `δ = 0.5^(Δ/h)` | `0.280616` | `0.928425` |
| `m`（`f = 0.5925`，现行） | `0.706851` | `0.970833` |
| **`q`（`f = 0.5925`，现行）** | **`0.535793`** | **`0.660167`** |
| `m`（`f = 0.62`，历史/用户脚本） | `0.726634` | `0.972801` |
| **`q`（`f = 0.62`，历史/用户脚本）** | **`0.550788`** | **`0.661505`** |

**前五行是输入，其余各行全部由输入算出。** 此前表格省略 `i` 与 `μ` 两行、只给出乘积
`w_i (i/10)`，读者无从核对——按该表反解得到的 `i` 为 `7` 与 `4`，而独立复算取 `4` 与 `5`，
两者 `r` 不同（`0.839` 对 `0.758`）。省略输入行是文档缺陷，与算术无关。
`μ` 在真实代码中由实体匹配算出，此处作为例题输入给出。

**判定（两列结论相同，因为比值不变）：**

```
f = 0.5925:  m_B/m_A = 1.373463 > 1.114706 = r_A/r_B   ⇒ q_B > q_A，B 胜出
f = 0.62 :  m_B/m_A = 1.338778 > 1.114706 = r_A/r_B   ⇒ q_B > q_A，B 胜出
```

余量有两种口径，引用时必须指明是哪一种：

| 口径 | `f = 0.5925`（现行） | `f = 0.62`（历史） |
|---|---|---|
| 比值余量 `m_B/m_A − r_A/r_B` | `0.258757` | `0.224072` |
| 分数余量 `q_B − q_A` | `0.124374` | `0.110717` |

（`audit_appendix.py` 的「余量」一行用的是**比值余量**。）

**临界 floor。** 对这对候选解 `m_B/m_A = r_A/r_B`，其中 `m = δ + (1−δ) f`：

```
m_A = 0.280616 + 0.719384 f          m_B = 0.928425 + 0.071575 f

(0.928425 + 0.071575 f) / (0.280616 + 0.719384 f) = 1.114706

⇒  f* = 0.842939
```

即 **floor 超过 `0.842939` 时这对候选的次序才反转**；采纳值 `0.5925` 与原默认值 `0.70`
都在其下，两者都判 B 胜出。`f*` 由 `δ_A`/`δ_B`/`r_A/r_B` 决定，**不含 `f`**，
因此换 `f` 不移动翻转点——**它比「试一个 `0.70` 看是否反转」更精确**。

> 本表 `f = 0.62` 列由 `experiments/user_a4_candidate_a.py` 与 `_b.py` 的运行输出逐格确认
> （`r = 0.758000`、`δ = 0.280616`、`m = 0.726634`、`q = 0.550788`；
> `r = 0.680000`、`δ = 0.928425`、`m = 0.972801`、`q = 0.661505`）。
> `f = 0.5925` 列与 `f = 0.62` 列**都由 `tools/audit_appendix.py` 双列复核**（逐格通过，见 A.6）。
