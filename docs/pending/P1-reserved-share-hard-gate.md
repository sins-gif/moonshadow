# P1 · 把「常驻区占比」（G4）从警告升级为硬门

| 项 | 内容 |
|---|---|
| **目标版本** | v1.2.x（与待办 `#19` 常驻区上限同一批） |
| **想法** | `recall` 装箱时 `T0/T1` 无条件进入常驻区、不受配额。现在 `tools/stress_recall.py` 的 `G4` 只报警不判红。等 `#19` 给常驻区加上限之后，`G4` 应当变成**硬门**：常驻区占预算超线就是失败，而不是警告 |
| **可实现性** | **解锁条件**：`#19` 落地（`pack` 里常驻区受比例上限约束）。**判定方法**：`python tools/stress_recall.py --cards 1000,10000` 的输出里，两档 `G4 常驻` 都显示 `✓`。**改法**：`verdict()` 把 `G4_reserved_share` 从 `soft` 移到 `hard`，并更新模块 docstring 的判据表 |
| **当前状态** | **未解锁**——实测常驻区占比：1k 卡 `41%`、10k 卡 `448%`、30k 卡 `1322%`（上限 `30%`） |

## 为什么现在不能硬

硬门今天会**永久红**：`T0/T1` 无条件进常驻区是设计行为，不是 bug；把缺陷状态下的一条判据设成硬门，
只会让整个工具失去信号（红灯常态 = 没有信息）。

## 解锁后的验收

- `1000` 与 `10000` 两档 `G4` 均 `✓`；
- `--strict-*` 之外不再需要用参数才能约束它；
- 同步更新 `tools/stress_recall.py` docstring 的「硬/软」表与 `docs/v1.2-perf-model.md` §8。
