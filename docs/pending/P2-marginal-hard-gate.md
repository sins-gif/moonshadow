# P2 · 把「边际台阶」（G2b）从警告升级为硬门

| 项 | 内容 |
|---|---|
| **目标版本** | v1.2.x（与待办 `#19` / backlog 第 6 条同批） |
| **想法** | `1000 → 1500` 卡之间有一个 `240 ms` 的台阶（边际 `581 ms/千卡`，之后回落到 `244–275`）。现在 `G2b` 只报警。归因查清并修掉之后，`G2b` 应当成为**硬门**：出现台阶就是失败 |
| **可实现性** | **解锁条件**（两条都要）：① `backlog.md` 第 6 条的归因有结论（是 SQLite 页缓存、还是 `card_text` 的 bigram 构造，二选一，要有 profiling 证据）；② 修完后 `python tools/stress_recall.py --cards 1000,1500,3000` 的相邻边际全部 `≤ 300 ms/千卡`。**判定方法**：上面的命令里 `G2b 边际` 全部 `✓`。**改法**：`verdict()` 的 `G2b` 由 `main()` 的后置判定移进 `hard`，去掉 `--strict-marginal` 的需要 |
| **当前状态** | **未解锁**——实测边际：`1000→1500` 是 `581`、`15000→20000` 是 `339`，都超 `300` |

## 为什么现在不能硬

它今天**必然红**（`581 > 300`），而且归因没有结论——把「不知道原因的现象」设成硬门，
下次它变红了没人能判断是回退还是原本就这样。

## 解锁后的验收

- `--cards 1000,1500,3000` 与 `--cards 5000,10000,20000` 两组都不再出现台阶警告；
- `--strict-marginal` 可以被删除（或保留为兼容别名）；
- 同步更新 `docs/v1.2-perf-model.md` §2 的实测表。
