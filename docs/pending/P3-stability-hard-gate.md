# P3 · 把「稳定性 IQR」（G5）从警告升级为硬门

| 项 | 内容 |
|---|---|
| **目标版本** | v1.2.x |
| **想法** | 现在 `G5` 用 `IQR/中位 ≤ 25%` 判抖动，只报警。但它对**双峰**不敏感：`1500` 卡档实测 `min 203 ms / 中位 382 ms`（`max/min = 1.95`），而 `IQR/中位` 只有 `4.6%`，判「稳定」。要让稳定性门真正可信，得先解决双峰盲点 |
| **可实现性** | **解锁条件**：给出一个对双峰敏感的**稳健**统计量并验证它不误报（候选：把 `max/min` 与 `IQR/中位` 组合成「两者任一超线即报」；或改用 `MAD` + 分位数尾部比）。**判定方法**：用 `--cards 1000,1500` 复现双峰（`max/min ≈ 1.9–3.1`）时新统计量报红，而 `--cards 1000,2000,3000` 这些单峰档保持绿。**改法**：`verdict()` 的 `G5` 换成新统计量，并移进 `hard` |
| **当前状态** | **未解锁**——统计量还没定；实测 `IQR/中位` 在 `1.2%–7.5%`，双峰档 `max/min` 到 `3.06` |

## 为什么现在不能硬

两个理由：① 判据本身有已知盲点（对双峰不敏感），硬门会在真出问题时放过；② 抖动幅度依赖机器负载，
把噪声设成硬门容易误报。**先用更稳的统计量，再谈硬门。**

## 解锁后的验收

- 双峰档报红、单峰档保持绿（两个方向都要测）；
- 连续跑三次，判定结果**一致**（稳定性门自己不能抖）；
- 同步更新 `docs/v1.2-perf-model.md` §7（区间统计那一节）。
