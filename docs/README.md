# docs 索引

**唯一权威是 [`v1.2-spec.md`](v1.2-spec.md)**（定义、契约与参数定值）。
其余**现行**文档只**引用**它，不重述它的定值——重述就会漂移。

**历史版本（[`v1.1-*`](v1.1-spec.md)、[`v1.0-moonshadow.md`](v1.0-moonshadow.md)）与现行文档并列保留**：
它们的价值是**留下推理链**——当时为什么那样想、哪条路被否决、错误是怎么被发现的。
但**其中所有数据一律不作为依据**；引用它们必须同时说明这一点。

## 2 阅读顺序

1. 根目录 [`../README.md`](../README.md) —— 这是什么、怎么跑起来；
2. [`v1.2-summary.md`](v1.2-summary.md) —— 现状与「哪些结论已经作废」；
3. [`v1.2-spec.md`](v1.2-spec.md) —— 契约与定值（动手前必读）；
4. [`v1.2-weights.md`](v1.2-weights.md) —— 结论背后的推理与实验；
5. 需要时再进 [`v1.2-candidates.md`](v1.2-candidates.md) / [`v1.2-roadmap.md`](v1.2-roadmap.md)；
6. 想追溯推理链时读历史版本，**只读其思路，不取其数字**。

## 3 权威分工：同一件事只有一处说了算

| 内容 | 唯一来源 | 其他文档的写法 |
|---|---|---|
| 定义 1–6、层级与半衰期、硬门规则 | `v1.2-spec.md` §2 | 只引编号，不重定义 |
| 参数**定值**（`f` / `θ` / 权重 / 采纳方案） | `v1.2-spec.md` §5.7 | 只引用，不重述定值 |
| 定理、证明、上界 | `v1.2-weights.md` §4 与附录 A | 引用定理编号 |
| **一切实测数字** | **工具输出**（`tools/*.py`） | 文档里的数字必须能由 §4 的命令复算；不能复算的要标「未复核」 |
| 用例集切分与冻结 | `eval/split-manifest.json` | 文档描述它，不复制哈希 |
| 批次能否合入 | `tools/run_batch_audit.py` 的判定 | §7.1 定义规则，工具负责判决 |
| 历史版本的任何数字 | **不作为来源** | 只能作为「当时如此」的记载引用，并注明历史地位 |

**冲突时的优先级**：工具输出 > `v1.2-spec.md` > 其他现行文档 > 历史版本。
也就是说，`v1.2-weights.md` 的散文如果与工具输出矛盾，是散文错。

## 4 维护规则

1. **定值只在 spec 出现一次。** 改参数要先改 `src/moonshadow/scoring.py`，再改 spec §5.7，
   然后跑 `python tools/audit_docs.py` —— 它会让其他文档里残留的旧赋值式立刻现形。
2. **数字以工具输出为准。** 写进文档的每个数字都应能指到某条命令；指不到就标「未复核」。
   散文会过期，数字过期的样子看不出来，所以宁可少写数字、多写命令。
3. **结论失效时写明失效与原因**，不要静默删除。`v1.2-summary.md` §4 与
   `v1.2-weights.md` 的差异表就是为此保留的——「曾经这样想、因为 X 不再成立」比删掉更有信息量。
4. **历史版本只加标注，不改内容。** `v1.1-*` 与 `v1.0-moonshadow.md` 记的是当时的取值与想法，
   今天看「不一致」属正常；允许追加状态标注，**不得改写其中的结论与数字**。
   现行文档引用它们时，同一行必须写明其历史地位（`audit_docs.py` 会检查这一点）。
5. **文档必须被分类。** `docs/` 下每份 `.md` 要么是索引、要么前缀是现行版本 `v1.2`、
   要么前缀已登记在 `audit_docs.py` 的 `HISTORICAL_PREFIXES` 里。升版时把旧前缀挪进去——
   这是一个有意动作，不会自动发生。
6. **加了文档就登记本索引**（§5 清单），否则 `tools/audit_docs.py` 会判违规。
7. 改完文档跑：`python tools/audit_docs.py` 与 `python -m unittest discover -s tests`。
