## 2 核心机制

**相关性是排序主轴；时间是门、有界修正与冲突裁决，不与相关性并列加权。**

```
r = w_σ σ + w_i (i/10) + w_μ μ          σ = (1+s)/2
δ = 0.5 ^ (Δ / h)                        h = 半衰期，h = 0 表示不衰减
m = f + (1 − f) δ                        f = 0.62
q = r · m
```

三重职责分工：

| 时间的作用 | 位置 | 说明 |
|---|---|---|
| 门 | 定义 6 | 按层级限制卡龄窗口（T4–T5 ≤ 30 天、T6–T7 ≤ 7 天） |
| 有界修正 | `m` | 最多把相关性打 `f` 折，**无法反转差距较大的相关性** |
| 冲突裁决 | `claim.valid_from` | 同一 `(subject, predicate)` 上更晚者胜 |

## 3 核心结论

### 3.1 加性融合不可用——形式不可分离

v1.0 的 `a = 0.45σ + 0.25δ + 0.20(i/10) + 0.10μ` 存在正负例对使 `a_N > a_P`：

```
负例 N（T3, i=2, Δ=10, s=0.15, μ=0）    a_N = 0.530219
正例 P（T5, i=3, Δ=120, s=0.70, μ=0.5） a_P = 0.493157
```

召回 P 要求 `θ < 0.493157`，排除 N 要求 `θ > 0.530219`——**互斥**。
根因是 `0.25δ` 一项在 `r` 中没有对应物：新鲜但无关的卡白拿分数。
**这是必须更换融合形式的依据，不是调参问题。**

### 3.2 有界修正给出与数据无关的保证

```
顺序可被时效性反转  ⟺  r_A / r_B  <  m_B / m_A  ≤  1 / f = 50/31 = 1.612903
```

相关性差距 ≥ `1.612903` 倍时，时间无法翻转次序。`f` 由 `0.70` 降到 `0.62`，
等价于把可反转区间从 `(1, 1.428571)` 放宽到 `(1, 1.612903)`。




### 3.3 `f = 0.62` 是交集中点

| 集合 | 全通过窗口 | 宽度 | 中点 |
|---|---|---|---|
| 开发集（11 条） | `[0.608, 0.634]` | `0.026` | `0.621` |
| 留出集（10 条） | `[0.466, 0.664]` | `0.198` | `0.565` |
| **交集** | `[0.608, 0.634]` | `0.026` | **`0.621`** |

采纳值 `0.620` 距下界 `+0.012`、距上界 `+0.014`（minimax）。
**留出集只否掉了 `0.70`，没有确认 `0.62`**——它宽度是开发集的 `7.6` 倍，分辨不出精确值。
`0.55 / 0.60 / 0.63 / 0.64` 在留出集上同样全对。

### 3.4 意图识别不做

换上正确默认值后，按意图切换 `f` 在开发集只有 `0.909`，**低于**固定值的 `1.000`；
留出集并列 `1.000`。**没有增量，却引入一个 recall 仅 `0.500` 的组件。**

## 4 六次自我推翻

这份记录真正的价值在这里——每一轮都改变了技术路线。

| # | 曾经的判断 | 被什么推翻 | 教训 |
|---|---|---|---|
| 1 | 「融合算术不重要」（n=6 时三种算术全 `0.833`） | 扩到 n=11，RRF 掉到 `0.727` | 小样本上的「无差异」不等于「无差异」 |
| 2 | 「上下文来源是关键路径」 | 消融显示固定值更好，意图切换无增量 | 把「机制不足」与「参数不当」分清 |
| 3 | 「留出集验证了 `0.62`」 | 分边算窗口：留出集宽 `7.6` 倍，只否掉 `0.70` | 留出集更宽时不构成独立约束 |
| 4 | 「权重分配无关紧要」 | 可行区占 `38.9%`，但当前值距边界仅 `0.0224` | 区域大 ≠ 取值稳 |
| 5 | 附录 A.4 的六位小数（手算） | 写成断言后查出 **7 个数字**在第 5–6 位有误 | 文档数字只有两个可靠来源：代码输出，或断言 |
| 6 | 「候选都过了硬门」 | 审计发现 **9 张正例**超出其层级卡龄窗口 | 用例的前提也要被审计 |

第 5 条的修正过程见 `docs/v1.1-weights.md` 附录 A.4；第 6 条见下文「已知缺陷」。

## 5 已核验 / 未核验

### 5.1 有数据支撑

| 参数 | 依据 | 数值 |
|---|---|---|
| `f` | 两集合窗口交集的中点 | `0.62` |
| `θ` | 标定区间 `[0.3878, 0.4074]` | `≈ 0.3976` |
| `θ′` | 标定区间 `[0.3326, 0.3997]` | `≈ 0.36615` |
| 乘性上界的有效性 | 2304 组配对，零违反 `1/f` | — |
| 加性形式不可分离 | 反例 + 阈值穷举（10001 个取值，可行解 0 个） | — |

### 5.2 未被任何数据约束（占位值）

| 参数 | 状态 |
|---|---|
| 相关性权重 `(0.60, 0.27, 0.13)` | 来源是 v1.0 权重按 `0.75` 重归一化；可行区占 `38.9%`，但当前值距边界仅 `0.0224`（2 个网格步），最稳点在 `(0.37, 0.18, 0.45)`，余量 `0.1552` |
| 10 个半衰期 | 从未做过扫描；全部实验按给定值计算 |
| 两个卡龄窗口（`30` / `7` 天） | 实验只对「已过门的候选」排序，未覆盖门本身 |
| 加性四项权重 | 未被约束，且其形式已被否证 |

### 5.3 漂移敏感性（2304 组参数网格）

| 方案 | 反转组数 | 占比 | 最大 `r_P/r_N` | 越过 `1/f` |
|---|---|---|---|---|
| 加性 | 173 | 7.51% | **1.8844** | **142** |
| 有界乘性 | 4 | 0.17% | 1.5845 | **0** |

加性方案的反转条件含一个与相关性无关的年龄偏移（`0.25δ`），因此卡龄分布漂移会让它的反转增长，
且**不受任何比值上界约束**；乘性方案的反转在任何卡龄分布下都不会越过 `1/f`。
严格说：漂移会让 `f` 的最优值变，但不会让「有界」这个保证失效。

## 6 已知缺陷（4 项，均未修）

1. **9 张正例候选超出其层级卡龄窗口**——开发集 `03`/`04`/`05`/`06`/`08`/`09`，
   留出集 `H02`/`H03`/`H05`。按定义 6，这些卡在真实流水线中会被窗口挡掉，
   相应用例的排序期望不会被执行。**修它会牵动 `f` 的可行窗口。**
2. **相关性权重停在可行区边缘**（余量 `0.0224`）。修它需先解决第 1 点，否则边界会移位。
3. **切换尚未落地**：`select()` 的默认 `scheme` 仍是 `additive`，`θ/θ_high` 仍是 `0.35/0.55`
   （两者都在标定区间之外）。因此 `f = 0.62` 对当前默认路径**零影响**。
4. **抽取基线压缩率 `0.35×`（在膨胀 token）**：因 SPEC 要求 T0/T1「保留原文」，
   基线把整段原文抄进 `raw_quote`。LLM 抽取器未接入。

## 8 如何复跑全部验证

全部命令在仓库根目录执行；均不依赖第三方包（Python 3.10+）。

| # | 命令 | 验证什么 | 预期 |
|---|---|---|---|
| 1 | `python -m unittest discover -s tests` | 151 个断言：原始层寻址、卡区幂等、打分与装箱、精度关卡、抽取管道、评测、常量与定理、附录算例、漂移上界 | `Ran 151 tests` + `OK` |
| 2 | `python tools/run_eval.py` | **抽取评测关卡**：关键字段保留率与压缩率双指标 | 退出码 `0`；会打印压缩率 `< 1` 的 WARN（已知状态） |
| 3 | `python tools/run_rank_eval.py` | 排序方案对照 + 意图评测 + `θ` 标定 + `floor` 扫描 + 逐用例可行区间 | 退出码 `0`（产出证据，不设阈值） |
| 4 | `python tools/run_holdout.py` | 开发集 vs 留出集的策略对比 + 两集合窗口交叉验证 | 退出码 `0`；应打印「留出集窗口更宽 → 起约束作用的是开发集」 |
| 5 | `python tools/run_drift_check.py` | 参数漂移下的反转区域（加性 vs 有界乘性） | 退出码 `0`；应打印「加性 142 组越界 / 乘性 0 组」 |
| 6 | `python tools/run_case_audit.py` | 用例集与硬门卡龄窗口的一致性 | 退出码 `0`，**但会报告 9 项违规**——这是已知缺陷，不是命令失败 |
| 7 | `python tools/audit_appendix.py` | 附录 A.3/A.4 的数值复核：从输入重算并与文档字面值逐格比对 | 退出码 `0` + 「复核通过」 |
| 8 | `python examples/demo.py` | 端到端演示：原文冷存 → 短卡 → 取代 → 回取 → 召回 → 装箱 → 升降级 → 精度校验 | 退出码 `0`，打印 9 步 |
| 9 | `python experiments/user_a4_candidate_a.py`（及 `_b.py`） | 附录 A.4 两个候选的独立复算（用户自算记录，原样保存） | 退出码 `0`；输出与附录 A.4 逐格一致 |

**第 6 条要特别注意**：它以「审计」而非「关卡」的形式存在，因此报告违规时仍返回 `0`。
在窗口一致性修好之前，这是预期输出。
