# 撤回记录（withdrawn claims）

> **这里只放「被撤回的对外宣称」。**
> 不放 bug 修复（那是 [`CHANGELOG.md`](../CHANGELOG.md)），不放「还没做」（那是 [`backlog.md`](../backlog.md)
> 与 [`v1.2-future-llm-extractor.md`](../v1.2-future-llm-extractor.md)），也不放「调参没调好」。
>
> 撤回一条宣称等于**公开承认**：那句话在当前版本里不成立。所以每条都必须能回答三件事：
> **撤回于哪个版本**、**为什么撤回**（可复算）、**什么条件下能重新宣称**。

## 文件命名

`W` + 编号 + `-` + 英文短名 + `.md`，编号从 `W1` 递增、**不复用**；中文标题写在文件里。
文件名保持 ASCII，因为守卫会从反引号里抽路径去查可达性（反引号里只写**真实存在**的路径）。

## 每个文件必须含三要素（`tools/audit_docs.py` 会检查）

| 要素 | 要求 |
|---|---|
| `撤回于` | 形如 `撤回于 v1.2.2`。必须指向**真实版本**：已打 tag 的 tag 存在，未打 tag 的当前版本由 `__version__` 兜底 |
| `原因` | 必须给**可复算**的依据（哪条命令、什么读数、机制是什么），不能只写「效果不好」 |
| `重启条件` | 可判定的条件（某条命令的读数达到某值），不写「以后再说」 |

## 还要写两段（守卫不强制，但读者需要）

- **撤回的不是什么**：同一版本里哪些结论照旧成立，各带复算命令。
- **替代路线**：现在往哪走了。

## 纪律

1. **权威在这里**：`CHANGELOG.md`、`v1.2-spec.md`、`v1.2-summary.md`、README 都只写
   「已撤回，见 W1」，**不复制原因**。
2. **撤回 ≠ 全盘失败**：只撤回那一句话。同一版本里用其它证据支撑的结论不受牵连。
3. **永不删除**：被撤回的记录是「当时为什么那样想」的证据，删掉等于抹掉推理链。
