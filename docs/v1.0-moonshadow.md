T0-T9 时间分层上下文压缩与记忆协议

版本： v1.0

> **历史版本 · 思考过程记录（保留，不作为当前依据）。**
> 保留它是为了可追溯推理链：当时为什么那样想、哪条路被否决、错误是怎么被发现的。
> **其中所有数据一律不作为依据**——当前协议与定值见 [`v1.2-spec.md`](v1.2-spec.md)，
> 当前数字一律以工具输出为准。本文件按当时状态保留：只允许追加状态标注，不得改写其中的结论与数字。
定位： 本地优先、可回溯、精度不丢的上下文压缩与时间记忆系统
核心思想： 原文冷存，短卡分层，T0-T9 定重要度，时间定衰减，按需召回，精确时回取原文。
1. 目标

    解决上下文过长、读取慢、Token 消耗大的问题。

    压缩后不丢失关键事实：日期、数字、金额、人名、URL、代码、否定词、条件、因果、承诺、决策、待办、截止时间。

    所有摘要必须可回溯到原文，通过 source_id 回取。

    本地可控、可审计、可回滚。

    不追求绝对无损压缩，追求“用的时候精度不丢”。

2. 核心原则

    原文永久保存： 压缩只生成短卡和索引，不替代原文。

    T0-T9 分层： 重要性定层级，时间定衰减，访问频率定升降。

    短卡运行时： 给 LLM 的上下文只放短卡，不放长文本。

    source_id 回链： 任何摘要都能定位到原始消息或文档块。

    冲突不覆盖： 旧记录标 superseded_by，新记录标 supersedes。

    按需召回： 查询时混合检索，只召回相关记忆。

    精确时回取原文： 需要原话、数字、代码时，按 source_id 解压原文块。

    本地优先： 敏感信息本地加密，不默认上传云端。

3. 三层架构
层	存什么	格式	作用
原始层	所有对话/文档原文	JSONL + zstd 分块	永不丢失，精确回取
记忆卡层	压缩后的短卡	JSON / MessagePack	运行时上下文
索引层	全文索引 + 向量索引	SQLite FTS5 + sqlite-vec/FAISS	快速召回

目录示例：
text

memory/
  raw/
    2026-09-30.jsonl
  cards/
    2026-09-30.jsonl
  chunks/
    2026-09-30.zst
  index.sqlite
  profile.md
  summaries/
    daily/
    weekly/

4. T0-T9 分层定义
层级	含义	半衰期	召回策略	存储
T0	永久核心：身份、硬约束、安全、法律	不衰减	永远召回，保留原文	热层 + 原文缓存
T1	长期关键：长期偏好、核心目标、关系	365 天	默认召回，保留原文	热层
T2	季度关键：项目决策、重要承诺	180 天	相关或未完成时召回	温层
T3	月度重要：近期待办、截止	90 天	相关时召回	温层
T4	周度重要：一般方案、讨论结论	30 天	近 30 天且相关时召回	温层
T5	日常事实：一般信息、偏好片段	14 天	低权重召回	温层
T6	短期上下文：当前任务细节	7 天	仅近期召回	冷层
T7	临时细节：中间推理、草稿	3 天	强相关才召回	冷层
T8	低价值：寒暄、确认	1 天	明确回溯才召回	冷层
T9	噪音：无意义内容	小时级	可丢弃，原文短期保留	冷层/丢弃

规则：

    重要性定 T 层。

    时间只负责衰减和召回，不直接决定 T 层。

    访问频繁升 1 级；长期未访问降 1 级；T0/T1 不降。

    冲突不覆盖，只标记新旧关系。

6. 触发机制

以下任一条件满足，启动异步整理：

    会话空闲 10 秒。

    累计 Token 达到 4096。

    累计消息数达到 10 条。

    出现 T0-T2 重要信息。

    检测到冲突、决策或承诺。

    触发后不阻塞当前交互，后台执行压缩流程。

7. 核心动作：Retain / Recall / Reflect

(结合 y8y 的三层动作分离)
A. Retain（记住：抽取与整合）

    信息抽取（Extraction）： 抽取事实、决策、待办、约束、偏好、承诺、日期、数字、否定、条件。

    实体消解（Entity Resolution）： 将代词归到真实对象（如“他” -> “张三”），实体之间连边成图。

    记忆整合（Consolidation）： 按 T0-T9 合并、去重、冲突标记。旧卡标 superseded_by，新卡标 supersedes。

    向量化（Embedding）： 生成向量，写入 sqlite-vec 或 FAISS。

    写入长期记忆： 短卡写入 cards/，原文继续冷存 raw/ 和 chunks/。

压缩提示词模板：
text

你是“时间加权记忆压缩器”。输入是带时间戳的对话/文档。
输出 JSON 数组，每个元素是一张记忆卡。

必须保留：日期、数字、金额、人名、地名、产品名、URL、代码、否定词、条件、因果、承诺、偏好、决策、待办、截止时间。

时间规则：
1. 最近24小时：保留细节和关键原话。
2. 最近7天：保留事件、结论、待办、变更。
3. 更早：只保留长期结论、偏好、关系、项目状态、未完成事项。

T层规则：
T0 身份/硬约束，T1 长期偏好，T2 项目决策，T3 近期待办，
T4 一般方案，T5 日常事实，T6 短期细节，T7 临时草稿，
T8 寒暄确认，T9 噪音。

实体规则：必须消解所有代词为具体实体。
冲突规则：冲突不合并，旧卡标 superseded_by。
不确定写“不确定”，禁止编造。
每条必须带 source_ids。

B. Recall（回忆：检索与召回）

四路并行检索：

    语义相似度： 向量距离。

    关键词匹配： BM25 / FTS5。

    图查询： 递归 CTE 查询，按共享实体扩展。

    时间过滤： 按时间区间筛选。

召回策略：

    T0-T1：无条件加入。

    T2-T3：相关或未完成时加入。

    T4-T5：近 30 天且相关时加入。

    T6-T7：近 7 天且强相关时加入。

    T8-T9：仅明确回溯或需要原话时加入。

排序公式：
text

score =
  0.45 * 语义相似度
+ 0.25 * exp(-Δ天数 / half_life_days)
+ 0.20 * priority / 5
+ 0.10 * 任务/实体匹配

(注：half_life_days=0 表示不衰减，如 T0/T1)
C. Reflect（反思：总结与判断）

    不要只是罗列召回的记忆卡，要串联成叙事。

    带因果与观点演变（如：“用户对某技术的看法从 A 变成了 B”）。

    召回提示词模板：

text

你是“上下文召回器”。当前时间：{{now}}。
用户问题：{{query}}
Token预算：{{budget}}
候选记忆：{{candidates}}

任务：
1. 按相关度、时间新鲜度、重要度、任务依赖排序。
2. 最近3天原始消息优先保留。
3. 相关记忆卡其次。
4. 如果记忆卡不足以精确回答，列出需要回取原文的 source_ids。
5. 输出组装后的上下文，分为：
   [长期偏好/约束]
   [近期原文]
   [相关记忆卡]
   [决策与待办]
   [冲突提示]
6. 不要加入候选之外的信息。

8. 冲突与精度保障

    冲突不覆盖： 旧卡 superseded_by，新卡 supersedes。

    原文双写： 原文永久保存，摘要可重建。

    关键字段原样保留： 数字、日期、金额、URL、代码、否定词、条件。

    压缩后校验： 用另一个模型检查是否遗漏日期、数字、否定、条件、承诺、偏好。

    敏感信息本地加密。

    保留策略： T0-T2 原文永久保存；T3-T5 原文保存；T6-T9 可短期保存。

9. 存储与索引选型

    热层： 内存 LRU 缓存，常驻 T0-T2 短卡和热点原文块。

    温层： SQLite + FTS5，存元数据和 T3-T5 摘要。

    冷层： zstd 压缩原文块，按 source_id 寻址。

    向量索引： sqlite-vec / FAISS / HNSW，存 int8/float16。

    列存可选： DuckDB / Parquet，用于大批量分析。

    推荐单机栈： SQLite + FTS5 + sqlite-vec + zstd + LRU 缓存 + MCP Server。

10. 接口设计

    MCP Server： moonshadow-memory-mcp，让 Claude、Cursor 等客户端直接调用。

    轻量 SDK： Python / TypeScript，两行代码写入和召回。

    标准文件格式： JSON Schema 公开，别人可不用你的代码也能存。

    本地优先： 数据默认存本地，云端只同步加密摘要。

11. 最小实现路线

    Phase 1（数据契约）： 定义 schema.json。强制校验，建立地基。

    Phase 2（抽取管道）： 写 compress.py。丢一段对话进去，按提示词模板输出 T0-T9 短卡。先跑通这一步，不碰向量。

    Phase 3（存储与检索）： 用 SQLite 建表。用 FTS5 建全文索引。写一个 recall.py，走一遍分数公式。

    Phase 4（精度回取）： 实现 source_id 原文块读取。给定 ID，读取精确的原始文本片段。

    Phase 5（整合）： 包装为 MCP Server。动态更新 access_count、last_access、T 层升降级。

12. 一句话总结

原文冷存，T0-T9 短卡分层，索引向量缓存按需召回，精确时回取原文，做到快、短、准、可回溯。
