# 运行时成本模型（性能）

> **这份文档只管一件事**：召回一次要多久，以及这个时间随卡数怎么长。
> 它**不定义任何协议**——定义、契约与定值仍以 [`v1.2-spec.md`](v1.2-spec.md) 为唯一权威；
> 本文不重述 `f` / `θ` / 权重，也不参与召回质量的判定。
>
> **全部数字都可复算**：数据来自 `python tools/stress_recall.py`，拟合用本文 §3 的闭式最小二乘
> （正规方程写出来了，Excel 也能重算）。**不要引用本文的数字而不说复算命令。**

---

## 1 这份文档为什么存在

`tools/run_*` 那一批回答的是「排序对不对、门挡不挡、切分冻没冻」——全是**正确性**。
没有一个回答「库长到一万张卡，一次召回要几秒」。而性能会**单独退化**：正确性可以一直绿，
延迟却随卡数增长。`tools/stress_recall.py` 的门限就是从这里来的，门限的数学依据也在这里。

## 2 实测数据

同一台机器、`realistic` 层级比例、每档丢弃首个预热样本后取 **5 次中位数**：

| 卡数 `n` | 召回中位耗时 `T` (ms) | 相邻档边际 (ms/千卡) |
|---|---|---|
| 10 | 5.0 | — |
| 100 | 12.5 | 82 |
| 500 | 46.1 | 86 |
| 1000 | 91.8 | 91 |
| 1500 | 382.5 | **581** |
| 2000 | 517.7 | 270 |
| 3000 | 761.9 | 244 |
| 5000 | 1307.4 | 273 |
| 10000 | 2682.5 | 275 |
| **20000** | **6068.1** | **339** |

复算：

```powershell
python tools/stress_recall.py --cards 10,100,500,1000 --repeats 5 --warmup 1
python tools/stress_recall.py --cards 1500,2000,3000,5000,10000,20000 --repeats 5 --warmup 1
```

**这条曲线不是一条直线，也不是一条干净的曲线**：`1000 → 1500` 之间有一个 `240 ms` 的台阶
（边际 `581`，比前后都高），之后回落到 `244–275`，在 `10000 → 20000` 又升到 `339`。
台阶的归因**未证实**，登记在 [`backlog.md`](backlog.md)（假设是 SQLite 默认页缓存装不下）。

## 3 三种候选函数形式与闭式解

设 `n` 为卡数、`T(n)` 为耗时的中位值。

### 3.1 仿射：`T = a + b·n`

正规方程：

```
[ Σ1   Σn ] [a]   [ ΣT  ]
[ Σn   Σn²] [b] = [ ΣnT ]
```

解出 `a`、`b`。**边际成本 `T'(n) = b` 是常数**——这是仿射模型最强也最脆的假设。

### 3.2 幂律：`T = c·n^k`

两边取对数退化成仿射：`ln T = ln c + k·ln n`，用同一组正规方程在 `(ln n, ln T)` 上拟合。
`T'(n) = c·k·n^(k-1)`，**边际随 `n` 增长当且仅当 `k > 1`**。

### 3.3 二次：`T = a + b·n + c·n²`

以 `n̄` 为中心（避免法方程病态），`u = n − n̄`：

```
[ Σ1   Σu   Σu² ] [a]   [ ΣT  ]
[ Σu   Σu²  Σu³ ] [b] = [ ΣuT ]
[ Σu²  Σu³  Σu⁴ ] [c]   [ Σu²T]
```

`T'(n) = b + 2c·(n − n̄)`，**`c > 0` 即凸**（边际递增）。

## 4 拟合结果（区间 `1500 – 20000`）

为什么是这个区间：`≤ 1000` 是台阶之前的另一套机制，混进来会把截距拉成另一个数（见 §6）。

| 模型 | 参数 | `R²` | **最大逐点误差** |
|---|---|---|---|
| 仿射 `a+b·n` | `a = −165.1 ms`、`b = 0.3063 ms/卡` | **0.9969** | **23.1%** |
| 幂律 `c·n^k` | `c = 0.1622`、**`k = 1.0588`** | 0.9967 | 4.3% |
| 二次 `a+b·n+c·n²` | `a = 1803`、`b = 0.2793`、**`c = +4×10⁻⁶`** | **1.0000** | 3.2% |

逐点残差（仿射偏差最大）：

| 卡数 | 实测 ms | 仿射拟合 | 相对误差 |
|---|---|---|---|
| 1500 | 382.5 | 294.3 | **−23.1%** |
| 2000 | 517.7 | 447.4 | −13.6% |
| 3000 | 761.9 | 753.7 | −1.1% |
| 5000 | 1307.4 | 1366.3 | +4.5% |
| 10000 | 2682.5 | 2897.7 | +8.0% |
| 20000 | 6068.1 | 5960.6 | −1.8% |

### 结论 1（方法上的教训）：`R²` 高不等于模型对

仿射的 `R² = 0.9969`，看上去几乎完美；但**截距是负的**（`−165 ms`，物理上不可能），
且 1500 卡处误差 **23%**。它靠抬高斜率同时迁就两端的数据，中间全部偏大。

**判定标准必须是逐点残差，不是 `R²`。** 这条对本文之外也成立：
本仓库所有「拟合得很好」的说法，都该配一张残差表。

## 5 边际成本 = 一阶导数

| 区间 | 实测边际 `ΔT/Δn` (ms/千卡) |
|---|---|
| 1000 → 1500 | **581**（台阶） |
| 1500 → 2000 | 270 |
| 2000 → 3000 | 244 |
| 3000 → 5000 | 273 |
| 5000 → 10000 | 275 |
| **10000 → 20000** | **339** |

三个模型给出的 `T'(n)`：

| 模型 | `T'(10000)` | `T'(20000)` | 与实测的关系 |
|---|---|---|---|
| 仿射 | `306` | `306` | **恒定**，与「实测在涨」矛盾 |
| 幂律 | `295` | `308` | 微涨，幅度偏小 |
| 二次 | `301` | **`372`** | 最接近实测的加速（实测 339） |

### 结论 2：成本是**凸**的，仿射只是区间近似

`k = 1.0588 > 1` 与 `c = +4×10⁻⁶ > 0` 从两个独立的方向指出同一件事：**边际成本随规模上升**。
所以「`T = a + b·n` 配一个 `b` 走全程」在数学上不成立，只能在有限区间内当近似。

## 6 两个截距不是矛盾，是分段

同一批数据能拟合出两个截距：

| 拟合区间 | 截距 | 斜率 |
|---|---|---|
| `10 – 1000` | **`+4.1 ms`** | `87.7 ms/千卡` |
| `1500 – 20000` | **`−165.1 ms`** | `306.3 ms/千卡` |

两者都对各自的区间成立。**「两套参数」本身就是分段线性的定量证据**，
也是「小库那个 `4.1 ms` 固定开销」的出处（`tools/stress_recall.py` 的 `A = 15 ms` 由它推出）。

## 7 外推：同一批数据，三个模型分歧 35%

用 §4 的参数外推到 `n = 50000`（**没有实测**）：

| 模型 | `T(50000)` |
|---|---|
| 仿射 | 15,149 ms |
| 幂律 | 15,330 ms |
| 二次 | **20,433 ms** |

### 结论 3：拟合好 ≠ 能外推

三个模型在 `1500–20000` 上都「拟合得不错」（`R² ≥ 0.9967`），外推 2.5 倍规模却差 **35%**。
所以门限**不能靠外推**：`tools/stress_recall.py` 已实现 `--verified-up-to`（默认 `20000`），
超出就标「外推」并把速度门降级为警告。**超过 `20000` 的工程解法见 backlog 最后一条。**

## 8 对门限的三条直接影响

| 项 | 现值 | 性质（必须写清） |
|---|---|---|
| `A`（固定开销） | `15 ms` | 由小库截距 `4.1 ms` × `3.7` 推出；**倍数 `3.7` 是假设**（未在 CI 机器上验证） |
| `B`（边际上限） | `300 ms/千卡` | **不是物理边际**，而是 `1500–20000` 区间仿射拟合的等效斜率 `306` 取整。幂律给 `295`、二次给 `301→372` |
| 有效范围 | `≤ 20000` | 之外为外推；`20000` 档实测已贴边（多次运行在 `5750–6068` 之间，门限 `6015`）——**那一档的判定本身不稳**，余量约 `0.9%`，而跨运行抖动 `3–10%` |

`--verified-up-to`（默认 `20000`）**已实现**：`cards > 该值` 时速度门降级为警告并标 `[外推]`，
要按外推硬判得加 `--strict-extrapolated`。

## 9 未知项（不许当结论用）

1. **`> 20000` 没有实测**。早前一次「50000 卡 18 s」用的是另一个生成器、`n = 1`，
   **不能引用**。
2. **跨机器完全没测过**。CI 容器、沙箱、磁盘冷热可能整体差 2–3 倍。
3. **合成分布不等于真实分布**。本文的卡文本是合成的；真实卡更长，绝对数字只会更差。
4. **台阶的归因未证实**。`1000 → 1500` 的 `240 ms` 台阶假设是 SQLite 页缓存，见 backlog。

## 10 与代码的关系

- 数据与门限：`tools/stress_recall.py`（含门限推导的数字，与本文一致）；
- 判据的数学被 `tests/test_stress_gate.py` 钉住（仿射门在小库成立、速度门用中位数、
  边际门能抓台阶）；
- 超过 `20000` 卡的工程解法不是调门限，而是减少每次召回的工作量（`card_text` 预计算、
  bigram 落库）——依据是本文 §5 的二次项，登记在 backlog。

**一句话**：这份文档存在的目的，是让「一次回收要多久」这件事**有公式、有残差、有边界**，
而不是只有一句「大概两秒」。
