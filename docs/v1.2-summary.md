## 2 核心机制与定值

**相关性是排序主轴；时间是门、有界修正与冲突裁决，不与相关性并列加权。**

```
r = 0.60 σ + 0.27 (i/10) + 0.13 μ        σ = (1+s)/2
δ = 0.5 ^ (Δ / h)                         h = 半衰期，h = 0 表示不衰减
m = f + (1 − f) δ                         f = 0.5925
q = r · m
```

| 参数 | 定值 | 来源 |
|---|---|---|
| `TIME_FLOOR`（`f`） | **`0.5925`** | 开发集窗与留出集窗**交集** `[0.5225, 0.6600]` 内近似居中的取值（下侧余 `0.0700`、上侧余 `0.0675`）。**中点依赖扫描步长**，不写「精确中点」——见 §4.2 |
| `THETA` | **`0.3941`** | 乘性量纲下两集合标定区间的建议值（开发集区间 `(0.386948, 0.401191)`，中点 `0.394069`） |
| `THETA_HIGH`（`θ′`） | **`0.3941`**（`θ′ = θ`） | **取消** `T6/T7` 的独立更高门槛；`T6/T7` 与 `T4/T5` 的区别只由卡龄窗口表达 |
| 采纳方案 | **`multiplicative`**（固定下限） | 并列满分时按「自由度更小」选定；`scoring.select()` 默认即生产配置 |
| 相关性权重 | `(0.60, 0.27, 0.13)` | v1.0 加性权重去掉衰减项后按 `0.75` 重归一化（推导，非判断） |
| `FLOOR_SWEEP_STEP` | `0.0025` | 必须整除 `0.5925`（`237` 步） |
| 卡龄窗口 | `T4–T5 ≤ 30` 天、`T6–T7 ≤ 7` 天 | 定义 6 |
| 半衰期（天） | `T0 0`、`T1 365`、`T2 180`、`T3 90`、`T4 30`、`T5 14`、`T6 7`、`T7 3`、`T8 1`、`T9 1/24` | `tiers.py`（唯一权威） |

三重职责分工：

| 时间的作用 | 位置 | 说明 |
|---|---|---|
| 门 | 定义 6 | 按层级限制卡龄窗口；负例的 `exclude` 是**断言**，由门审计强制 |
| 有界修正 | `m` | 最多把相关性打 `f` 折；`1/f = 1.687764` 是次序可被反转的比值上界 |
| 冲突裁决 | `claim.valid_from` | 同一 `(subject, predicate)` 上更晚者胜 |

## 4 已失效的结论（**不要再用**；附失效原因与现值）

### 4.1 加性 `θ` 的「不可行」要分清三层

旧文档写「加性方案 `θ` 不存在可行区间」，未区分范围。精确表述分三层：

| 层 | 陈述 | 依据 |
|---|---|---|
| **定理（构造性）** | 存在正例 `P` 与负例 `N` 使 `a_N > a_P`，故**任何**单一阈值都无法同时召回 `P` 与排除 `N`。反例对 `N = (T3, i=2, Δ=10, s=0.15, μ=0)`、`P = (T5, i=3, Δ=30, s=0.72, μ=0)`，`a_N = 0.530219`、`a_P = 0.503608`。两条都满足自身层级的卡龄窗口，且分属不同用例 | 定理不依赖用例集；`v1.2-weights.md` §4.3 与附录 A.3 |
| **全标注集测量** | 开发集 ∪ 留出集：`(0.503608, 0.530219)`，**不可行** | 见证对的正例 `17` 已划入留出集，把正例下界压到 `0.503608 < 0.530219` |
| **开发集测量** | 开发集单独：`(0.530219, 0.550015)`，**可行**，中点 `0.540117` | `17` 不在开发集，`θ` 在开发集上可分离 |

因此：**「加性 `θ` 不可行」的成立范围是全标注集，不是开发集**；定理本身是构造性的，不依赖任何用例集。

### 4.2 单一 `f` 的可行窗不是 `0.026`，现值是 `0.1600`；且「中点」依赖扫描步长

| | 旧结论（v1.1） | 上一版（23 条） | 现值（26 条，`run_holdout.py`） |
|---|---|---|---|
| 开发集窗 | `[0.608, 0.634]`，宽 `0.026` | `[0.470, 0.685]`，宽 `0.215` | **`[0.5000, 0.6600]`，宽 `0.1600`** |
| 留出集窗 | `[0.466, 0.664]`，宽 `0.198` | `[0.525, 0.980]`，宽 `0.455` | `[0.5225, 0.9800]`，宽 `0.4575` |
| 交集 | `[0.608, 0.634]`，宽 `0.026` | `[0.525, 0.685]`，宽 `0.160` | **`[0.5225, 0.6600]`，宽 `0.1375`** |

**原因（两条）**：① 旧窄窗是用例 `03-task-continuation` 一张**超出 T5 窗口**的候选卡
（`Δ=120` 天）造出来的，改写为窗口内卡龄后窗口放宽约 8 倍——「`f` 的精度是假精度、`f` 不可辨识」**失效**；
② 本轮按 R1 新增 `23`/`24`/`25` 三条边界用例后窗口由 `0.215` 收窄到 `0.1600`，
**钉住窗口的用例也换了**：上界 `0.6600 ← 23-t6-tight-race`、下界 `0.5000 ← 24-t7-borderline`。

**必须收窄的第二条旧结论**：「`0.605` 是交集的精确中点、偏离 `0.0000`」**不成立**。
中点是**扫描步长依赖**的量：`0.005 → 0.5925`、`0.0025 → 0.5913`、`0.00125 → 0.5919`、
`0.0005 → 0.5922`，真值约 `0.592 ± 0.001`。现行采纳值 `0.5925` 与当前步长（`0.0025`）下的
交集中点 `0.5913` 相差 `0.00125`——**恰好半个步长**。诚实表述是
「落在交集内、到两端余量近似相等（下 `0.0700`、上 `0.0675`）」，不是「精确中点」。

### 4.3 区分力不是「消失」，而是「用例给不给」——本轮它回来了

旧结论写「本用例集对融合形式已无区分力（五方案并列满分）」。**本轮失效**：
加入 3 条边界用例后，两个**依赖上下文来源**的方案掉到 `0.962`。

| 方案 | v1.1（11 条） | 上一版（23 条） | 现值（26 条，`run_rank_eval.py`） |
|---|---|---|---|
| 加性 | `0.970` | `1.000` | `1.000` |
| 乘性修正（采纳） | `1.000` | `1.000` | `1.000` |
| 乘性 + 按意图硬切换 | `1.000` | `1.000` | `1.000` |
| 乘性 + 连续敏感度插值 | `1.000` | `1.000` | **`0.962`** |
| 两种分数 50/50 平均 | `0.970` | `1.000` | **`0.962`** |
| 仅相关性 + 时间破同分 | `0.636` | `0.783` | `0.731` |
| RRF 名次融合 | `0.727` | `0.812` | `0.756` |

**两个掉下来的方案都且只在 `24-t7-borderline` 上失败**，工具原文是
`FAIL 24-t7-borderline 期望=older-more-relevant > newer-less-relevant 实际=newer-less-relevant > older-more-relevant`。
**原因不是漏判**：`24` 的查询含「现在」，敏感度被**正确**识别为 `1.0`，下限因此被压到
`TIME_FLOOR_MIN = 0.35`，时间话语权变大，更新但相关性更低的 `T7` 翻盘。
**区分力是用例给的，不是方案自己冒出来的**——上一版说「无区分力」，是因为用例集缺边界用例。
方向也因此更明确：**把「时间话语权」交给上下文反而更差**，支持固定下限。

仍然成立的部分：**加性的缺陷在一致率表上看不出来**（它也是 `1.000`），
只能靠阈值可分离性（定理，§4.1）与合成网格实验（§5.6）来否定。

### 4.5 留出集窗口仍不包含开发集窗口

旧文档写「留出集窗口完整包含开发集窗口，宽 `7.6` 倍」。现值：留出集 `[0.5225, 0.9800]`、

仍然成立：留出集窗口宽得多（`0.4575` vs `0.1600`），因此它只能否掉极端值。

### 4.6 `θ′` 取 `0.3941` 动用了一次留出集验证

开发集单独标定 `θ′` 的建议值是 **`0.412684`**（区间 `(0.330863, 0.494506)`）。
但两集合并后 `θ′` 的正例下界降到 `0.397591`（留出集三条 `T6` 正例的最小 `q`），
**`0.412684` 落在区间外被否决**，于是采纳 `θ′ = θ = 0.3941`——
两集合同时成立的区间是 `(0.386948, 0.397591)`。
**代价必须记账**：留出集的一次性已被 `f = 0.5925` 与 `θ′` 这两处使用，后续决策需要新的留出集。

旧批 7 条的相邻最小分差：`0.1208 / 0.1402 / 0.0091 / —（无相邻对）/ —（无相邻对）/ 0.2213 / 0.0533`，
**全部可行宽度 `1.000`**——`20` 的 `0.0533` 仍越过 `0.05` 的线。
**原因**：重划切分后原来提供约束的两条（`17`、`21`）被分到**留出集**，开发集侧只剩 7 条且全部对 `f` 无约束。

**必须这样读**：R1/R2（`v1.2-roadmap.md` §7.1）是**前瞻性**规则，不是对已合入批次的追认；
重划切分会让旧批次在新开发集上不再达标。把 §7.1 的规则读成「全部已通过」是误读。

**新增（本轮修掉的一个度量缺陷）**：R1 原先只比「相邻最小分差」，用的是**绝对值、不含方向**，
于是「在当前采纳下限下排序已经错了」的用例也会因分差小被算作边界用例。
现在 `Row.passes_at_adopted` 强制要求**边界用例必须是当前采纳下限下排序正确的用例**，
排序错误的单列为失败项。读 R1 的数字时要知道这条已经收紧。

### 4.9「漏判无害」只在采纳方案下成立

上一版写「所有漏判都无害」。**必须限定范围**：它只在**采纳方案（乘性固定下限）**下成立。
`24-t7-borderline` 上失败的**连续插值与 50-50 平均**，失败原因**不是漏判**，
而是「现在」被**正确**识别后下限被压到 `TIME_FLOOR_MIN = 0.35`（§4.3）。
也就是说：漏判确实没造成排序错误，但**识别生效**同样能造成排序错误——两者不是一回事。
