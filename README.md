## 核心特点

- **纯 Python 标准库实现，零第三方依赖**（Python 3.10+）——`import` 里没有 numpy，也没有任何数据库驱动之外的东西。
- **采用有界乘性修正算法**（`q = r · m`，`m ∈ [f, 1]`），规避加性融合的**阈值不可分离**缺陷：
  同一批用例上，加性方案在合成网格里于乘性方案**有保证**的区域仍反转 `117` 组，乘性越界 `0` 组；
  其排序一致率**也并列满分**（`1.000` vs `1.000`）——**排序指标看不出的缺陷，由阈值与漂移实验暴露**。
- **236 项单元测试 + 14 条审计/验证命令**：参数与数据严格受控——用例的卡龄窗口与门前置、
  负例是否真被门挡住、留出集是否被改动、文档里的赋值式是否与代码一致，**全部可执行、可复跑**。

## 快速开始

无需安装任何依赖（Python 3.10+，纯标准库）：

```bash
python -m unittest discover -s tests   # 确定性测试：条数与状态以本命令输出为准（本次交付实测 Ran 236 tests + OK）

# 审计与契约（四条，均应为 0 违规）
python tools/run_case_audit.py          # 用例的卡龄窗口与 T8/T9 门前置
python tools/run_gate_audit.py          # 负例是否真被生产门挡住、reason 是否与实际规则一致
python tools/run_split_integrity.py     # 留出集是否被改动（冻结清单的 SHA-256）
python tools/audit_docs.py              # 文档守卫：链接、定值、索引

# 参数与证据
python tools/run_rank_eval.py           # 排序方案对照 + θ 标定 + floor 扫描
python tools/run_holdout.py             # 开发集 vs 留出集：结论是否过拟合
python tools/run_grouped_floor.py       # 分组时间下限两阶段扫描（v1.2-A 储备方案）
python tools/run_batch_audit.py            # 批次验收 R1/R2：默认判定「冻结后新增」那一批；不合格退出码 1
python tools/run_drift_check.py         # 参数漂移下的反转区域：加性 vs 有界乘性
python tools/run_network_eval.py        # network 赋值准确率与混淆矩阵
python tools/audit_appendix.py          # 附录数值复核：从输入重算并与文档字面值逐格比对
python tools/run_eval.py                # 抽取评测关卡：不达标即退出码非 0（会告警压缩率 < 1）
python tools/resplit_cases.py           # 按种子重划开发/留出集并写冻结清单（仅在决定新建留出集时运行）

python examples/demo.py                 # 端到端演示，打印每一步的设计依据
```

**当前采纳参数**（`scoring.select()` 的默认值即生产配置）：

| 参数 | 值 | 位置 |
|---|---|---|
| 融合方案 | `multiplicative`（固定下限） | `scoring.ADOPTED_SCHEME` |
| 时间下限 `f` | `0.5925` | `scoring.TIME_FLOOR` |
| 硬门阈值 `θ` / `θ′` | `0.3941` / `0.3941`（取消独立更高门槛） | `scoring.THETA` / `THETA_HIGH` |
| 相关性权重 | `(0.60, 0.27, 0.13)` | `scoring.RELEVANCE_WEIGHTS` |

`demo.py` 会走一遍完整链路：追加原文 → 压成 T0-T9 短卡 → 同源改写标记取代 →
冷存分帧 → 按 source_id 逐字回取 → 硬门召回打分 → 预算装箱降级 → 访问计费升降级 →
关键字段丢失判 FAIL。

## 评测关卡

`tools/run_eval.py` 对 `eval/gold/` 里的金标准跑抽取管道，报**两个**指标：

| 指标 | 含义 | 当前基线 |
|---|---|---|
| 关键字段保留率 | 日期/金额/URL/代码有没有丢（阈值 0.98） | 1.000 |
| 压缩率 | 原文 token / 卡 token，越大越好 | **0.498x**（逐用例平均）/ **0.487x**（token 加权） |

只盯保留率会被钻空子，只盯压缩率会丢字段。基线实测压缩率 **0.498x**——它在**膨胀** token，
因为 SPEC 要求 T0/T1「保留原文」，基线把原文整段抄进了 `raw_quote`，又把同一批字段逐句复述进
`facts`/`decisions`/`todos`。这是符合规范的基线代价，不是 bug：它标出了「不丢字段」的召回上限，
模型抽取器的任务是在保持该保留率的同时把压缩率做到 > 1。关卡会对此显式告警。

工具还会按 `T0–T9` 打印**分层读数**（卡数 / 原文 token / 卡 token / 压缩率 / 卡 token 占比）。
它把「膨胀出在哪一层」变成可指的数字：当前 `T0` 只有 `0.412x`（原文逐字抄进 `raw_quote`），
`T2`/`T3` 是 `0.383x`/`0.393x`（整句复述），`T6` 有 `0.977x`（纯叙述没有字段可复述）。
未产出卡的层级显示为 `—`（不可观测），不是 `0.00x`（压缩得很差）。
两个压缩口径与适用域见 `docs/v1.2-spec.md` §9.2–§9.3：**金标准集已从 3 条短用例扩到 25 条
（其中 22 条长会话）**，因为原文只有一句话时任何系统都做不到 > 1x，那个规模上这个指标不可解释。

## 排序方案对照实验

「时间该不该和相关性抢权重」不靠争论，靠数据。`tools/run_rank_eval.py` 用 **26 条**开发用例
（历史决策 / 当前状态 / 任务跟进 / 长期偏好 + 负例、对抗用例与边界用例）比较七种方案，
七种方案都调用同一份真实打分代码：

| 方案 | 融合算术 | 上下文来源 | 成对一致率 | 失败 |
|---|---|---|---|---|
| 加性（v1.0 的 `0.45/0.25/0.20/0.10`） | 加性 | 无 | `1.000` | 0/26 |
| **乘性修正（采纳，固定 `f = 0.5925`）** | 乘性 | 无 | **`1.000`** | **0/26** |
| 仅相关性 + 时间破同分 | 无 | — | `0.731` | 7/26 |
| 乘性 + 按意图硬切换 | 乘性 | oracle 意图 | `1.000` | 0/26 |
| 乘性 + 连续敏感度插值 | 乘性 | 措辞推断 | `0.962` | 1/26 |
| RRF 名次融合 | RRF | 措辞推断 | `0.756` | 7/26 |
| 两种分数 50/50 平均 | 分数平均 | 措辞推断 | `0.962` | 1/26 |

**这张表现在有区分力了**：三个方案并列满分（加性 / 乘性固定下限 / 意图硬切换），
而两个**依赖上下文来源**的方案掉到 `0.962`——**两者都且只在 `24-t7-borderline` 上失败**。
原因不是漏判：`24` 的查询含「现在」，敏感度被**正确**识别为 `1.0`，下限因此被压到
`TIME_FLOOR_MIN = 0.35`，时间话语权变大，更新但相关性更低的 `T7` 翻盘。
**区分力是用例给的，不是方案自己冒出来的**——上一版说「无区分力」，是因为用例集缺边界用例。

同一套用例还跑 **θ 标定** 与 **floor 扫描**，这两项才是关键：

| 检查项 | 结果 |
|---|---|
| 时间敏感度识别（二分类，已知是错的中间指标） | 准确率 `0.731`、状态类 recall `0.500`、precision `0.857` |
| **floor 落带率**（正确的中间指标） | **`26/26`**——采纳值 `0.5925` 落在每条用例的可行区间内 |
| 采纳方案 `θ` 标定（乘性，开发集） | 区间可行 `(0.386948, 0.401191)`，建议 `0.3941`（= 现行值） |
| 采纳方案 `θ′` 标定（乘性，开发集） | 建议 `0.412684`，**被留出集否决**，故 `θ′ = θ = 0.3941` |
| 加性方案 `θ` 标定 | 开发集可行 `(0.530219, 0.550015)`；**合并留出集后不可行**（负例上界 `0.530219` > 正例下界 `0.503608`） |
| **全局 floor 扫描** | 全对窗口 `[0.500, 0.660]`，宽 `0.160`，中点 `0.5800` |

四条结论：

1. **加性方案的阈值不可分离**：新鲜但无关的卡靠 `0.25δ` 这一项白拿分数，分数反超真正相关的卡。
   **排序一致率看不出这个缺陷（加性也是满分），必须做阈值标定才能看见**——
   在全标注集（开发 ∪ 留出）上，加性 `θ` 的可行区间是空集。
2. **融合形式的区分力回来了，但方向支持固定下限**：`24-t7-borderline` 把连续插值与
   50-50 平均打到 `0.962`；把「时间话语权」交给上下文反而更差。
   加性仍只能靠阈值可分离性（反例对 + 阈值穷举）与合成网格实验（`run_drift_check.py`：
   加性在乘性「有保证」的区域里反转 `117` 组，乘性越界 `0` 组）来否定——它的排序一致率是满分。
3. **「要不要意图识别」是伪二选一**：全局单值 `0.5925` 就能全对；
   意图切换没有增量（开发集 `0.923`，仍低于纯全局的 `1.000`），
   却引入一个状态类 recall 仅 `0.500` 的组件，属负收益。
4. **二分类意图准确率是错的中间指标**：开发集报 `7` 处漏判/误判，
   而按「floor 是否落在用例可行区间内」衡量的落带率是 `26/26`——**没有一处造成排序错误**。

**因此结论已落地为：默认方案 `multiplicative`、`f = 0.5925`、`θ = θ′ = 0.3941`，意图识别不做。**
（`θ/θ′` 已不再是加性量纲下的占位值 `0.35/0.55`。）

## 留出验证（结论所在）

开发集（`eval/rank`，**26 条**）用来提出假设，留出集（`eval/holdout`，**9 条**）用来检验假设。
留出清单由 `eval/split-manifest.json` **冻结**（种子 `20260601`），逐个文件记录 SHA-256；
改动留出集会被 `tools/run_split_integrity.py` 判违规（重划原因：v1.1 时代修用例时改过留出文件，
留出集已被开发过程污染）。标签用 `needs_fresh`（答案是否依赖最新状态）而不是意图分类——
后者对「报价给到了吗」没有客观答案。

| 策略 | 开发集 | 留出集 | 差值 |
|---|---|---|---|
| 全局 **`0.70`（v1.1 旧默认）** | `0.808` | `1.000` | `+0.192` |
| 全局 **`0.5925`（现行采纳值）** | **`1.000`** | **`1.000`** | `+0.000` |
| 全局 `0.55` | `1.000` | `1.000` | `+0.000` |
| 全局 `0.50` | `1.000` | `0.963` | `-0.037` |
| 全局 `0.35` | `0.885` | `0.889` | `+0.004` |
| 意图切换 默认 `0.70`/状态 `0.35` | `0.808` | `1.000` | `+0.192` |
| 意图切换 默认 `0.5925`/状态 `0.35` | `0.923` | `1.000` | `+0.077` |
| 连续插值 默认 `0.70` | `0.846` | `1.000` | `+0.154` |
| 连续插值 默认 `0.5925` | `0.962` | `1.000` | `+0.038` |

工具的输出照原样读：**开发集最优是 `0.5925`，留出集最优是 `0.70`**，
`run_holdout.py` 因此直接打印「**两者不一致 → 开发集上的最优是过拟合的直接证据**」，
以及「检验『`0.5925` 优于 `0.70`』：留出集 `1.000` vs `1.000` → **不成立**」。
**这条对照在留出集上不成立**——留出集上 `0.70` 不劣于 `0.5925`。

分边算可行窗口：

| 集合 | 窗口 | 宽度 | 中点 |
|---|---|---|---|
| 开发集（26 条） | `[0.5000, 0.6600]` | `0.1600` | `0.5800` |
| 留出集（9 条） | `[0.5225, 0.9800]` | `0.4575` | `0.7512` |
| **交集** | **`[0.5225, 0.6600]`** | **`0.1375`** | **`0.5913`** |

**与 v1.1 的记录相反，留出集窗口仍不包含开发集窗口**（其下界 `0.5225` 高于开发集的 `0.5000`），
但它宽得多（`0.4575` vs `0.1600`），所以只能否掉极端值、不能确认精确值。
钉住开发集窗口的是本轮新增的两条：上界 `0.6600` ← `23-t6-tight-race`，下界 `0.5000` ← `24-t7-borderline`。

采纳 `0.5925` 与交集中点 `0.5913` 相差 `0.00125`——**恰好半个 `FLOOR_SWEEP_STEP`（`0.0025`）**。
中点本身是**扫描步长依赖**的量：`0.005 → 0.5925`、`0.0025 → 0.5913`、`0.00125 → 0.5919`、
`0.0005 → 0.5922`，真值约 `0.592 ± 0.001`。所以**不能写「精确中点」**；诚实表述是
「落在交集内，且到两端余量近似相等（下 `0.0700`、上 `0.0675`）」。
**v1.1 的窄窗 `0.026` 是用例 `03` 一张超窗卡造出来的，该用例已修正，窄窗结论作废。**

**三条结论：**

1. **能独立确认的只有「`0.70` 对开发集太高」**——留出集在 `0.70` 上反而是满分，
   所以「`0.5925` 优于 `0.70`」这个检验**不成立**。`0.5925` 是交集内近似居中的取值，
   不是被验证过的真值。
2. **意图识别不必做**——换上更好的默认值后，意图切换在开发集仍只有 `0.923`（低于纯全局 `0.5925`），
   留出集并列 `1.000`：**没有增量，却引入一个状态类 recall 仅 `0.250` 的组件**，属负收益。
3. **二分类时效识别指标继续被证明是错的度量**——留出集状态类 recall `0.250`，
   三个漏判（`08`、`21`、`H07`）全部落在各自可行区间内，**一个都没造成排序错误**。
   （注意：开发集上 `24-t7-borderline` 的失败**不是漏判**——它的「现在」被正确识别，
   是识别**生效后**下限被压到 `0.35` 才翻盘的。）

边界：留出集同样是人工编写、与开发集共享同一套「数值世界」，检验的是**同类设计假设下的泛化**，
不是真实查询分布上的泛化。效力边界见 `docs/v1.2-weights.md` §7.3（威胁有效性）：
`n` 小、期望顺序与标记词表人工拍定、部分方案是看到数据后加入的、分数型负例只有 3 条
（`θ` 区间约束很弱）。

**留出集的一次性已经用掉一部分**：`θ′` 的开发集建议值 `0.412684` 被留出集否决，
采纳值改为 `θ′ = θ = 0.3941`。后续参数决策需要**新的**留出集。

> （`*.zip`/`*.tar.gz`/`*.bin`/`*.model`/`*.safetensors` 等）。真正的体积门禁需要

## 最小用法

```python
from datetime import datetime, timezone
from moonshadow import FixedClock, Store, make_card
from moonshadow.scoring import select
from moonshadow.pack import Item, pack

clock = FixedClock(datetime.now(timezone.utc))   # 生产用 SystemClock()
store = Store("./memory", clock=clock)

sid = store.append_message("session-1", "客户说预算 12 万，截止 2026-10-15。")
card = make_card(
    clock=clock, session_id="session-1", tier="T2", importance=8, network="experience",
    source_ids=[sid], summary="预算 12 万，截止 2026-10-15。",
    entities=["客户"], facts=["预算 12 万", "截止 2026-10-15"],
)
store.put_card(card)                      # 幂等：重复写返回 inserted=False

ranked = select(store.cards(), now=clock.now(), query_cos={card["id"]: 0.8})
store.archive_day(clock.now().date().isoformat())   # 归档后仍可逐字回取
assert store.get_raw(sid) == "客户说预算 12 万，截止 2026-10-15。"
```

## 三条不可退让的约束

1. **可回溯**：任何摘要都能按 `source_id` 取回逐字节原文，sha256 校验，冷存后依然成立。
2. **不静默丢信息**：T0/T1 无视预算常驻；冲突只标取代不覆盖；关键字段丢失判 FAIL。
3. **可复现**：时间一律注入，同输入必得同输出——否则生产事故无法复盘，验收指标也无法回归。
